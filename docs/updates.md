# 업데이트

egasu는 Mac 앱의 표준 업데이트 프레임워크인 [Sparkle](https://sparkle-project.org)로 스스로를 최신 상태로 유지.
업데이트는 egasu 릴리스 피드에서 내려받고, 설치 전에 Sparkle이 서명 검증.

## OpenUsage에서 egasu 1.0.0으로 전환

이름 변경 첫 정식 릴리스는 `egasu 1.0.0`이며 태그는 `v1.0.0`.
설치 파일은 `egasu-1.0.0.dmg`, 앱 이름은 `egasu.app`, 터미널 명령은 `egasu`.
기존 설치의 설정·계정·iCloud 기록을 이어 쓰기 위해 Apple Bundle ID와 iCloud 컨테이너 ID 유지.
`openusage.*` 저장 키·API 스키마, Keychain 서비스 이름, 기존 설정·데이터 경로도 유지.
이름 변경 때문에 계정을 다시 등록하거나 설정 파일을 옮길 필요 없음.

기존 Sparkle은 새 앱을 원래 설치 경로에 배치.
새 정식 앱의 첫 실행에서 `OpenUsage.app`을 같은 폴더의 `egasu.app`으로 변경한 뒤 재시작.
이 앱의 헬퍼를 가리키는 기존 `openusage`·`egasu` 명령 링크도 새 경로로 변경.
사용자가 정한 다른 앱 파일명, 다른 앱을 가리키는 링크, 개발용 앱은 변경하지 않음.
명령 링크 폴더에 쓰기 권한이 없으면 macOS 관리자 승인을 요청해 이 앱의 링크만 변경.
승인 대기 중 다른 프로그램이 바꾼 링크는 덮어쓰지 않음.
대상 `egasu.app`이 이미 있거나 앱 폴더에 쓰기 권한이 없으면 덮어쓰지 않고 오류 표시.
관리자 승인을 취소하거나 링크 변경에 실패하면 기존 앱 경로 유지.
명령 링크 변경 또는 재시작 예약 실패 시 앱과 이미 변경한 링크를 이전 경로로 복원.

이 포크의 `0.8.1`부터 `0.14.3`까지는 같은 Bundle ID와 기존 업데이트 주소 사용.
동일한 서명 신뢰 관계와 더 큰 빌드 번호를 유지하면 중간 버전 없이 새 정식 버전으로 업데이트 가능.
Sparkle은 표시 버전 `1.0.0` 대신 내부 `CFBundleVersion`으로 새 버전을 판단.
내부 빌드 번호는 기존 Git 커밋 수를 이어 사용하며, 이름 변경이나 메이저 버전 전환 때문에 초기화하지 않음.
`0.8.0` 이하의 원본 Swift 앱과 `0.6.x` Tauri 앱은 식별자·업데이트 서버가 달라 이 전환 대상에서 제외.

기존 앱은 계속 `https://openusage.chanhyung.kim/appcast.xml`을 조회.
새 정식 배포 항목을 기존 주소에서도 제공해야 하며, 새 도메인에만 게시하면 기존 앱은 발견하지 못함.
DNS·HTTPS·기존 피드 제공은 별도 인프라 단계이며, 앱 코드 변경만으로 기존 앱의 조회 주소가 바뀌지는 않음.

## 동작 방식

- **자동 확인.**
  앱이 백그라운드에서 조용히 새 버전을 확인(약 한 시간에 한 번).
  새 버전을 찾으면 다른 앱 뒤에 창을 띄우는 대신 팝오버 상단에 **Update Available**(업데이트 있음) 배너를 표시.
  **Install Update**(업데이트 설치)를 클릭하면 릴리스 노트·다운로드·설치가 담긴 업데이트 창이 앞으로 열림.
  배너의 닫기 버튼은 잠시 미루는 동작 — 앱이 그 업데이트를 다시 발견하면 배너도 다시 등장.
- **수동 확인.**
  언제든 **Settings → Updates**(설정 → 업데이트)를 열고 **Check for Updates…**(업데이트 확인…) 클릭.
  수동 확인이든 배너를 통한 설치든, egasu는 Sparkle을 열기 전에 스스로를 앞으로 가져와 업데이트 창이 다른 앱 뒤에 묻히지 않게 함.
  평소에는 메뉴 막대에만 있으므로, 업데이트 세션 동안만 Dock 아이콘을 잠깐 보여 준 뒤 다시 숨김.
- **끄기.**
  **Settings → Updates**의 **Update Automatically**(자동 업데이트) 스위치를 끄면 백그라운드 확인이 중단.
  수동 확인은 계속 가능.

## 베타 업데이트

**Settings → Updates → Beta Updates**(설정 → 업데이트 → 베타 업데이트)를 켜면 모두에게 배포되기 전의 프리릴리스 빌드까지 받게 됨.
끄면 안정 버전만 받는 상태로 돌아가고, 다음 안정 릴리스가 따라잡을 때까지 현재 버전을 유지.

안정 릴리스는 누구나 항상 받음 — 베타 옵션은 그 위에 프리릴리스 빌드를 *더할* 뿐.

## 업데이트 출처

업데이트 빌드는 egasu의 GitHub 릴리스에 게시되고, 사용 가능한 버전 목록("appcast")은 `https://openusage.chanhyung.kim/appcast.xml`에서 제공.
공식 릴리스의 앱과 DMG는 Developer ID로 코드 서명한 뒤 Apple 공증을 받음.
공증은 코드 서명과 별도 절차이며, 공증 결과를 앱과 DMG에 첨부.
업데이트 다운로드에는 Sparkle용 EdDSA 서명도 추가하고, Sparkle이 설치 전에 검증.
서명 검증에 실패한 업데이트는 설치 거부.
이 기능은 공식 서명 릴리스 빌드에만 있고 로컬 개발 빌드에는 없음.
로컬에서 `1.0.0` 전환을 확인할 때는 `EGASU_DEV_VERSION=1.0.0`으로 `1.0.0-dev` 번들 생성 가능.
정식 버전은 실제 릴리스 태그에서만 결정하며 개발 빌드가 정식 릴리스를 대신하지 않음.

## 유지 관리자: 게시 버전 보호

앱캐스트·가격표·사이트는 성공한 게시 작업이 전달한 커밋으로 함께 배포.
산출물이나 커밋 확인 실패 시 배포 중단 — 검증되지 않은 최신 브랜치로 대체하지 않음.

Pages 배포는 한 번에 하나씩 실행하고 대기 중인 배포도 보존.
`pages-deployment` 브랜치는 가장 최근에 배포를 시도한 게시 커밋을 가리키는 보호 기준.
새 배포는 이 기준과 같거나 그 이후 커밋만 허용하며, 과거 실행 재시도는 업로드·배포 생략.
기준 조회·전진 실패 또는 서로 갈라진 이력은 배포 중단.

첫 보호 배포는 현재 `gh-pages` head를 가리키는 성공한 게시 실행으로 초기화.
더 새로운 미검증 게시가 있으면 해당 게시를 수정·재실행한 뒤 초기화.
기준은 실제 배포 전에 전진하므로 이후 배포가 실패해도 유지되며, 같은 커밋의 배포 재시도 가능.
복구할 때는 기준 브랜치를 삭제하거나 강제로 되돌리지 않고 마지막 실패 배포를 재실행하거나 필요한 파일을 새 게시 커밋으로 복원.
이 보호 로직이 없는 과거 workflow 실행의 재시도 대신 현재 workflow에서 복구 진행.
