# Kiro

Kiro CLI에 이미 로그인된 계정의 코딩 크레딧 추적.

## 추적 항목

| 지표 | 의미 |
|---|---|
| Credits | 현재 결제 기간 한도 대비 사용한 크레딧과 초기화 시각 |

Kiro가 반환한 구독 이름도 표시.
보너스 크레딧과 초과 사용 상세 정보는 활성 응답 형식이 검증되지 않아 표시하지 않음.

## 상단 통계 지원 범위

이 Mac의 Kiro CLI V3 세션을 기존 Today·Yesterday·Last 30 Days의 Cost·Tokens·Cost/MTok에 반영.
원천은 `~/.kiro/sessions/<workspace>/<session>/messages.jsonl`의 턴별 사용량과 대화 이력.
계정의 월간 Credits 값과 로컬 기간별 통계는 서로 다른 범위.
로그를 읽기 전용으로 조회하며 대화 본문이나 인증 정보를 별도 저장하지 않음.

- 비용은 저장된 턴별 크레딧에 [공식 추가 크레딧 단가](https://kiro.dev/pricing/)인 `$0.04/credit`을 곱한 환산 추정치.
  포함 크레딧·무료 사용·할인·세금·구독료를 반영한 실제 청구액이 아님.
- [Crew 문서](https://kiro.dev/docs/crew/system/)와 같이 저장된 토큰 수가 없어 문자 길이로 추정.
  입력은 사용자 입력·도구 결과 뒤에 관측된 모델 응답마다 그 시점의 저장된 컨텍스트 길이를 4로 나누고 올림.
  저장된 `system` 메시지도 입력 컨텍스트에 포함.
  출력은 일반 답변 길이를 같은 방식으로 환산하며 도구 호출·추론 출력을 제외.
  압축 요약을 만드는 별도 요청의 입력·출력은 직접 집계하지 않으며, 저장된 요약은 이후 요청의 입력 컨텍스트에 포함.
  모델 전환 때 저장된 메모(`agent_note`)도 이후 입력 컨텍스트에 포함.
  이미지·로그에 없는 시스템 정보·하위 에이전트 내부 호출은 토큰 추정에서 제외.
- 같은 메시지의 갱신은 마지막 내용만 사용하고, 같은 실행 ID의 턴은 복사·fork된 세션에 있어도 한 번만 합산.
  되감기·압축으로 이후 컨텍스트에서 빠진 요청도 이미 소비한 사용량에는 유지.
  모델 전환 중 폐기된 메시지는 이후 입력 컨텍스트에서 제외하며, 폐기 전 소비한 사용량은 유지.
  하위 에이전트 크레딧은 부모 턴에 포함되므로 별도 하위 실행 파일에서 다시 더하지 않음.
- 응답 이력이 없는 유료 턴이 섞인 기간은 비용만 표시.
  읽지 못한 폴더·세션과 손상된 기록은 제외하고 읽을 수 있는 나머지 이력과 카드 경고 유지.
  로컬 스캔이 값을 반환하지 못하면 마지막 통계 수집일이 같은 경우에만 기존 통계 유지.
  통계 수집일은 한도 조회일과 별도로 보존하며, 한도 조회 실패 중 수집한 오늘 통계도 같은 기준 적용.
  세션 폴더(`~/.kiro/sessions`)가 사라져 이전 통계를 유지하는 경우에는 한도 조회 성공 여부와 관계없이 카드 경고 표시.
  정상적으로 빈 이력을 확인하거나 마지막 통계 수집일이 다르면 기존 통계 제거.
- 턴 사용량이 저장된 시각을 로컬 자정 기준 날짜로 묶어 집계.
  Last 30 Days는 기존 통계와 같이 오늘 및 이전 30일 포함.

지원 형식은 확인한 V3 세션 저장 형식 기준.
CLI 2.x의 별도 저장 형식과 이 Mac에 기록되지 않은 사용량은 포함하지 않음.
[CLI V3 ACP 문서](https://kiro.dev/docs/cli/v3/acp-migration/)의 세션 재생·턴별 계량 구조를 따르며, 내부 파일 형식 변경 시 수집기 갱신 필요.

## 인증 정보 출처

`~/Library/Application Support/kiro-cli/data.sqlite3`의 Kiro CLI 데이터베이스를 읽음.
액세스 토큰과 프로필은 읽기 전용이며, Kiro 인증 정보를 갱신하거나 쓰지 않음.

Kiro CLI 소셜 로그인만 지원.
Kiro IDE 상태, Builder ID 또는 Identity Center 인증 정보, `~/.kiro` 아래의 기기 로컬 세션 파일은 계정 할당량 소스로 사용하지 않음.

## 문제 해결

- **"Not logged in to Kiro"** — `kiro-cli login` 실행.
  소셜 로그인 완료 후 OpenUsage 새로 고침.
- **"Kiro session expired"** — `kiro-cli login` 다시 실행.
  소셜 로그인 완료 후 새로 고침.
- **"Kiro credentials could not be read"** — Kiro CLI 데이터베이스가 존재하고 읽기 가능한지 확인.

## 내부 동작

저장된 액세스 토큰과 프로필 ARN을 비공식 CodeWhisperer `GetUsageLimits` 엔드포인트로 전송.
401 또는 403 응답 후 데이터베이스를 한 번 다시 읽고, Kiro CLI가 이미 토큰을 교체한 경우에만 재시도.
