# OpenCode

> 2026-11-06 확인: 아래 Go 상한은 기존 방식의 추정치이며, 현재 Go·Go Plus·Go Teams의 모델별 사용량 한도와 다를 수 있음.
> 새 구독의 정확한 잔여량이나 Plus·Teams 등급 판정에는 사용 불가.

Mac에 이미 저장된 OpenCode 자체 로그를 사용해 OpenCode 호스팅 사용량(**Go** 구독과 **Console**, 종전 Zen 종량제 게이트웨이) 추적.
구독 가격과 현행 라인업은 [구독 요금제](/docs/pricing.md#구독-요금제) 참조.
원본 로그는 이 Mac에서만 읽음.

## 추적 항목

| 지표 | 의미 |
|---|---|
| Session | 최근 5시간의 로컬 Go 사용액과 $12 상한 |
| Weekly | 이번 주의 로컬 Go 사용액과 $30 상한(UTC 월요일 시작) |
| Monthly | 로컬 기록으로 정한 월간 기간의 Go 사용액과 $60 상한 |
| Today / Yesterday / Last 30 Days | 모든 OpenCode 호스팅 사용량(Go + Console)의 로컬 비용과 토큰 |
| Usage Trend | 최근 한 달간 토큰의 일별 스파크라인 |

로컬 Go 키 또는 지출·Go 집계 범위 안의 Go 기록이 있으면 프로바이더 이름 옆에 "Go" 표시.
서버에서 실제 구독의 활성·만료 여부를 확인하지 않음.

Session / Weekly / Monthly 미터는 **로컬에서 관측한 사용액**, 즉 *이* Mac에 기록된 사용량을 표시.
다른 기기의 사용량이나 아직 저장되지 않은 기록은 포함하지 않음.
미터와 재설정 시각은 이전 Go 방식의 로컬 추정값이며, 현재 계정의 실제 잔여 allowance와 다를 수 있음.
로컬 Go 키와 집계 범위 안의 Go 기록이 모두 없으면 Go 상한 미터 미표시.
Console 사용 기록은 지출 타일에 계속 반영.

## 인증 정보 출처

평소처럼 OpenCode 사용.
로컬 데이터 디렉터리의 `auth.json`에서 Go 키 확인.
사용액과 토큰 수는 SQLite 로그에서 계산.
OpenUsage의 데이터 디렉터리는 다음 순서로 결정:

1. OpenUsage 전용 override인 `OPENCODE_DATA_DIR`이 설정돼 있으면 해당 경로 사용.
2. 그 외에 `XDG_DATA_HOME`이 설정돼 있으면 `$XDG_DATA_HOME/opencode` 사용.
3. 두 환경 변수가 모두 없으면 `~/.local/share/opencode` 사용.

`OPENCODE_DB`가 설정돼 있으면 해당 DB만 조회.
절대 경로는 그대로, 상대 경로는 위 데이터 디렉터리 기준으로 해석.
쉘에서 확장되지 않은 `~/` 값도 데이터 디렉터리 아래 상대 경로로 해석.
`:memory:`는 다른 프로세스에서 읽을 디스크 로그가 없어 수집 불가.
DB 경로를 바꿔도 `auth.json` 위치는 데이터 디렉터리 기준 유지.

로그인 프롬프트나 붙여 넣을 토큰 불필요.

## 미터와 지출 타일

`step-finish` 기록이 있으면 각 step의 비용과 토큰을 합산.
step 기록이 없는 메시지는 메시지에 기록된 비용과 토큰 사용.
달러 금액을 OpenUsage에서 다시 계산하지 않음.
토큰 `total`이 없으면 입력·출력·추론·캐시 읽기·캐시 쓰기를 한 번씩 합산.
토큰 필드 자체가 없으면 비용은 유지하고 토큰은 0으로 처리.
토큰 필드가 있지만 값이 잘못되면 해당 기록 제외.
세션 fork가 복사한 과거 사용량은 중복 합산에서 제외.
같은 프로젝트에서 세션 생성 전 시각과 메시지 내용이 일치하는 기록을 복사본으로 판별.
비용 기록 후 fork하고 원본의 완료 시각·종료 상태·구조화 출력이 바뀌어도 같은 소비는 한 번만 합산.
같은 세션에 시각·내용이 동일한 메시지가 여러 개 있으면 각각의 소비 보존.
복사본만 남으면 세션별 동일 기록의 최대 개수만큼 유지.
fork 이후의 새 요청과 각 세션에서 새로 생성한 요청은 각각 합산.
OpenCode 버전에 따라 기록값 자체가 카탈로그 단가로 계산한 추정 비용일 수 있으며, 실제 청구액·Go allowance와 다를 수 있음.
OpenCode 자체 기록이 포함된 기간의 지출은 추정 비용으로 표시하고 내보낸 이력도 추정 비용으로 분류.
각 지출 타일은 Claude / Codex / Cursor와 동일하게 비용과 토큰을 함께 표시(`$4.08 · 1.2M tokens`).
검사 범위는 지출 타일보다 넓은 월간 Go 기간까지 포함.
현재 지출 타일과 Go 기간에 속하지 않는 과거 기록은 비용 합산에서 제외.
Console 기록은 지출 타일 기간에만 반영.
큰 유한 비용은 반올림 과정에서도 그대로 유지해 사용량 스냅샷 저장 가능.
지출 타일은 해당 기간에 사용 기록이 없으면 "No data" 표시.
Go 키가 있고 사용 기록이 없으면 상한 미터에는 $0 표시.
잘못된 숫자나 합산 범위를 넘기는 비용·토큰 행은 지출 타일·추세·Go 사용량에서 함께 제외하고 진단 로그에 기록.
나머지 정상 행은 계속 반영.
원본 로그는 이 Mac에서만 읽음.

현재 OpenUsage가 적용하는 이전 Go 상한은 **5시간당 $12**, **주당 $30**, **월당 $60**.
계정별 한도를 서버에서 조회하지 않음.

- **Session:** 최근 5시간의 기록 합산.
  사용 기록이 있으면 카운트다운은 가장 오래된 기록이 집계에서 빠지는 시각.
  이후 기록이 남아 있으면 그 시각에도 사용액이 0보다 클 수 있음.
- **Weekly:** UTC 월요일부터 다음 월요일까지의 기록 합산.
- **Monthly:** 이 Mac에서 읽은 가장 이른 Go 기록의 UTC 날짜·시각으로 월간 경계 계산.
  해당 날짜가 없는 달에는 그 달의 마지막 날짜 사용.
  최초 Go 기록을 확인하지 못하면 UTC 기준 매월 1일부터 집계.

Console 사용량은 Go 상한 계산에서 제외하고 지출 타일과 Usage Trend에 반영.

공유 도구가 `opencode` 또는 `opencode-go`로 기록한 사용량도 지출·토큰 이력에 반영.
추가 기록의 비용은 제공자가 보고한 금액만 사용하며 가격을 모르는 기록의 토큰은 유지.
해당 기간의 비용이 불완전하면 전체 비용·Cost/MTok 생략.
추가 도구의 기록은 Go 미터의 기간·상한 계산에 합산하지 않음.

## 문제 해결

- **모든 항목에 "No data" 표시** — `OPENCODE_DB`를 설정했다면 해당 DB, 아니면 데이터 디렉터리의 `opencode*.db` 확인.
  OpenCode 세션을 실행한 뒤 새로 고침.
  (Go에 로그인된 경우 첫 로컬 메시지 전에도 상한 미터에 $0 표시.)
- **Session / Weekly / Monthly 미터가 없음** — 로컬 Go 키나 지출·Go 집계 범위 안의 Go 기록이 있는지 확인.
  집계 범위 밖의 과거 기록만으로는 상한 미터가 나타나지 않음.
  키나 집계 범위 안의 기록이 남아 있으면 구독 만료 후에도 미터가 나타날 수 있음.
- **"Couldn't read OpenCode's local database"** — 데이터베이스(또는 데이터 디렉터리)가 있지만 이번 새로 고침에서 읽지 못한 상태.
  OpenCode를 종료하고 새로 고침한 뒤에도 문제가 계속되면 설정한 DB 또는 데이터 디렉터리의 접근 권한 확인.
- **일부 로컬 사용량 파일을 읽지 못했다는 안내** — 여러 DB 중 일부만 읽은 불완전 합계.
  누락된 DB의 권한·잠금 상태를 확인한 뒤 다시 새로 고침.
- **"Couldn't read OpenCode's auth.json"** — 파일이 있지만 읽을 수 없거나 유효한 JSON이 아닌 상태.
  권한을 확인하거나 OpenCode Go에 다시 로그인해 파일 재작성.
- **수치가 대시보드보다 낮음** — 미터는 로컬에서 관측한 사용액(이 Mac만 해당)으로, 위 설명 참고.

## 내부 동작

`OPENCODE_DB`가 없으면 데이터 디렉터리의 모든 `opencode*.db` 조회.
설정돼 있으면 지정한 DB 하나만 조회.
V1 `message`·`session` 및 선택적인 `part` 테이블 지원.
현재 V2 개발 버전의 `session_message`·`session_v2` 및 credential DB는 미지원.
안정 릴리스는 `opencode.db`, 일부 개발 채널은 `opencode-<channel>.db` 사용.
조회한 DB의 어시스턴트 메시지에서 `cost`와 토큰 필드를 읽음.
Go 상한에는 `opencode-go` 메시지를 합산하고, 지출 타일과 추세에는 `opencode-go`(Go)와 `opencode`(Console)를 모두 합산.
로컬 식별자 `opencode`와 과거 Zen 기록도 같은 Console 범위에 포함.
읽기 전용, 네트워크 미사용.
공식 사용량 API 연동은 미구현.

## 공유 도구 사용량

공통 수집 대상은 Pi·Oh My Pi(OMP).
도구별 경로·중복 제거·가격 규칙은 [사용량 수집](/docs/usage-collection.md) 참조.
계정 귀속을 확인하지 못하는 기록은 계정 전용 카드에 합산하지 않음.
공통 수집이 실행되면 읽지 못한 저장소를 경고하고 읽은 기록은 보존.
네이티브 이력의 실패 탐지와 화면 반영은 해당 provider의 수집 경로에 따름.
공유 도구 기록에는 제공자가 보고한 비용만 사용하며 단가표 추정액은 합산하지 않음.
모델 가격을 확인하지 못해도 토큰은 보존하고 해당 기간의 총비용 생략.
native 원장 읽기 실패 시 공유 도구의 정상 이력은 유지하고 Go 미터는 생략.
공유 도구의 정상 이력도 없으면 원장 읽기 오류 반환.
로컬 키나 native 사용 이력이 없어도 최근 집계 기간에 유효한 공유 도구 OpenCode 이력이 있으면 로컬 감지 대상에 포함.
다른 provider 기록이나 정상 빈 공유 파일만으로는 자동 활성화하지 않음.
이미 활성화한 카드는 정상 완료된 공유 스캔이 비어 있으면 이전 이력을 비우고 데이터 없음으로 표시.
native 원장이 없고 공유 이력이 빈 경우에도 `auth.json` 접근 실패는 경고로 안내하며, 완료된 빈 이력은 유지.
Go 키·native 원장·공유 스캔 결과가 모두 없으면 감지되지 않음 오류 반환.
