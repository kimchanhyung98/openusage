# Z.ai

코딩 구독용 [Z.ai](https://z.ai)(Zhipu AI) GLM Coding Plan 사용량 한도와 토큰 통계 추적.

## 추적 항목

| 지표 | 의미 |
|---|---|
| Session | 5시간 순환 기간의 크레딧 또는 토큰 할당량 사용 비율 |
| Weekly | 7일 순환 기간의 크레딧 또는 토큰 할당량 사용 비율 |
| Web Searches | 월간 웹 검색 / 웹 리더 / Zread 호출 횟수(사용 / 한도) |

Z.ai가 요금제 이름을 반환하면 프로바이더 이름 옆에 표시.
구독 이름 조회가 실패하면 할당량 응답의 `data.level`로 요금제 표시.
현행 Lite·Pro·Max의 월 정가·할인 표기·크레딧 한도는 [구독 요금제](/docs/pricing.md#구독-요금제) 참조.

상단 Tokens에는 개인 GLM Coding Plan의 일별 토큰 합계 반영.
Today·Yesterday와 공통 Last 30 Days 기간 지원.
Last 30 Days는 다른 공급자와 같은 오늘 및 이전 30일 범위.
카드 지표를 모두 숨겨도 활성화된 Z.ai의 토큰 합계는 포함.
Z.ai를 비활성화하면 상단 합계에서 제외.

모델별 캐시 입력·일반 입력·출력 토큰이 모두 확인되면 공통 [가격 엔진](/docs/pricing.md)으로 Cost·Cost/MTok 추정.
[Z.ai API 공개 요율](https://docs.z.ai/guides/overview/pricing) 기준의 추정치이며 실제 구독 청구액 아님.
구독료·할당량 비율·크레딧을 달러 비용으로 환산하지 않음.
시간별·일별 집계에는 개별 요청 길이가 없어 기본 요율 사용.
장문 요청 요율이나 Coding Plan의 비혼잡 시간대 배율은 적용하지 않음.
가격이 확인된 정확한 Z.ai 모델 키와 등록 별칭만 사용하며, 유사 모델이나 다른 호스팅 업체의 가격으로 대체하지 않음.
캐시 사용이 있으면 명시된 캐시 입력 단가 필요.
GLM-4.5 계열은 `zai/` 전용 보충 요율을 우선 적용.
캐시 입력 100만 토큰당 GLM-4.5·GLM-4.5V는 $0.11, GLM-4.5-Air는 $0.03, GLM-4.5-AirX는 $0.22, GLM-4.5-X는 $0.45 적용.
입력·출력 단가도 같은 Z.ai 공식 가격표 기준으로 유지.

비용과 토큰은 같은 모델별 상세 응답에서 함께 계산하여 Cost/MTok의 분모 일치.
알 수 없는 모델·누락된 토큰 분해·불완전한 날짜축이 있는 기간은 비용을 생성하지 않고 기존 일별 활동 토큰 유지.
활동 조회가 실패해도 날짜축과 모델별 토큰 분해가 완전하면 상세 응답의 토큰 합계 유지.
가격까지 확인되면 같은 상세 응답으로 비용도 표시.
상세 토큰은 완전하지만 가격을 확인하지 못하면 할당량과 토큰은 표시하고 비용은 생략.
팀·조직이나 일반 API 종량제 청구액은 이 통계 범위에서 제외.

## 인증 정보 출처

OpenUsage의 Z.ai 조회에는 사용자가 제공한 API 키 필요.
다음 순서에서 처음 찾은 키 사용:

1. `~/.config/openusage/zai.json` — `{"apiKey":"…"}`(API Key 카드에서 저장하는 파일)
2. `~/.config/zai/key.json`
3. `ZAI_API_KEY` 환경 변수
4. `GLM_API_KEY` 환경 변수(레거시 Zhipu 이름도 계속 지원)

파일을 직접 편집하지 않고 **Customize → Z.ai → API Key**에서 키를 추가하거나 교체 가능.
앱에서 키를 저장하거나 삭제하면 적용 중인 키로 새로 조회하며, 이전 요청이 진행 중이면 완료를 기다리고 그 결과는 무시.
이전 요청이 대기 한도보다 오래 걸리면 다음 주기 새로 고침에서 현재 키로 재시도.
비활성 프로바이더는 다시 활성화될 때 조회.
새 요청이 진행 중이거나 필수 할당량 조회가 실패하면 이전에 표시하던 마지막 정상 값 유지.
할당량 조회가 성공하면 이번 조회에서 확인된 토큰·비용 통계만 반영.
활동·상세 조회 실패로 확인할 수 없는 통계는 이전 값을 재사용하지 않고 안내 경고 표시.
활동 조회가 실패해도 완전한 기간의 상세 토큰은 사용.
모든 기간의 토큰을 확인할 수 있으면 활동 조회 실패는 진단 로그에만 기록.
정상 응답에서 모델 가격을 확인하지 못하면 토큰은 유지하고 비용만 생략.
기간 상세가 불완전하면 비용을 확정하지 않고, 활동 조회가 성공한 경우에만 해당 기간의 활동 토큰 표시.
상세 응답이 유효한 경우 이 집계 제약은 진단 로그에만 기록.
모델별 합계와 전체 합계가 맞지 않는 등 상세 응답이 유효하지 않으면 비용 안내 경고 표시.
앱 재실행 시에도 현재 키로 조회하기 전 마지막 값 복원 가능.
사용량 조회 시 API 키를 Z.ai 서버로 전송.

## 설정

1. [GLM Coding 요금제 구독](https://z.ai/subscribe).
2. [Z.ai 콘솔](https://z.ai/manage-apikey/apikey-list)에서 API 키 발급.
3. Customize의 프로바이더 목록에서 Z.ai 활성화.
4. Z.ai 상세의 API Key에서 Add 선택.
5. 발급한 키 입력.
6. Save 선택.

조회에 성공하면 대시보드에 사용량 표시.
메뉴 막대에도 표시하려면 해당 지표의 별표 선택.

### 환경 변수로 키 제공

API Key 카드에 저장하는 대신 셸 프로필에서 키 제공 가능.
저장된 키가 있으면 환경 변수보다 먼저 사용.

1. 셸 프로필(예: `~/.zshrc` 또는 `~/.zprofile`)에 다음 설정 추가.

   ```bash
   export ZAI_API_KEY="YOUR_API_KEY"
   ```

2. OpenUsage 종료.
3. OpenUsage 다시 실행.
4. Customize의 프로바이더 목록에서 Z.ai 활성화.

앱은 시작할 때 로그인 셸 환경을 읽음.
현재 터미널에서만 실행한 `export`는 이미 실행 중인 앱에 적용되지 않음.

## 내부 동작

Z.ai 구독 UI와 공식 ZCode가 사용하는 내부 엔드포인트 사용:

- `GET https://api.z.ai/api/biz/subscription/list` — 요금제 이름(가능한 범위에서 조회하며, 이 호출이 실패해도 미터는 비워지지 않음).
- `GET https://api.z.ai/api/monitor/usage/quota/limit` — 할당량 미터.
- `GET https://api.z.ai/api/monitor/credit-usage/activity` — 개인 Coding Plan의 일별 토큰.
- `GET https://api.z.ai/api/monitor/credit-usage/usage-detail` — 모델별 캐시 입력·일반 입력·출력 토큰.

제공자가 응답 형식이나 접근 방법을 변경하면 조회 실패 가능.
HTTP 200이어도 `success=false` 또는 실패 `code`가 있으면 할당량을 반영하지 않고 마지막 정상 값 유지.
성공 코드는 `0`·`200` 지원.

일별 토큰 계약은 [공식 ZCode의 Coding Plan 문서](https://github.com/zai-org/ZCode/blob/a9fe401eede6e6e5e01be9048679c206fe6f02d9/docs/bigmodel-coding-plan-usage-quota.md#L119)와 해당 버전의 요청·응답 구현 기준.
`type=1`과 로컬 날짜의 `startTime`·`endTime`을 전송하고, `data.series`의 `date`·`totalTokens` 사용.
공식 ZCode처럼 호출자 시간대로 날짜 경계를 만든 뒤 시간대 없는 날짜 문자열 전송.
별도의 UTC+8 변환은 적용하지 않음.
토큰·할당량·개인 구독 조회는 공식 ZCode와 같이 API 키 원문 인증 사용.
Bearer 접두사는 추가하지 않음.
중복 날짜·잘못된 값·요청 범위 밖 날짜는 유효하지 않은 통계로 처리.
기간 범위가 명확하지 않은 `summary` 합계를 일별 통계 대신 사용하지 않음.
토큰 조회 실패 시 할당량 미터를 유지하고 안내 경고 표시.
명시적인 빈 활동 배열은 정상적인 사용 이력 없음으로 처리.

모델 상세는 `type=1`·`usageType=MODEL`로 조회.
한 번에 최대 30일을 조회하는 공식 계약에 맞춰 이전 30일과 오늘을 나누어 요청.
이전 30일은 일별 축, 오늘은 시간별 축과 각 모델의 세 토큰 배열을 같은 인덱스로 연결.
과거 날짜 또는 오늘의 0시부터 현재 시간까지 축이 빠지면 해당 기간의 비용 미확정 처리.
미래 시간의 축은 요구하지 않음.
모든 모델 합계인 캐시·일반 입력·출력 행은 실제 모델 행과 중복 합산하지 않음.
전체 합계 행의 토큰 배열이 있으면 같은 시간·날짜의 모델별 합계와 대조.
합계가 다르면 해당 상세 응답의 비용을 확정하지 않고 활동 토큰과 안내 경고 유지.
모델 없이 전체 합계 행만 있으면 비용 미확정 처리.
빈 상세 응답이나 합계 범위가 명확하지 않은 모델 요약값으로 기존 활동 토큰을 덮지 않음.

할당량 응답에 `limits` 배열 포함.
`CREDIT_LIMIT`과 기존 `TOKENS_LIMIT` 항목은 할당량 사용 비율을 제공하며, 기간 길이에 따라 반영할 미터 결정(하루 미만 → Session, 여러 날 → Weekly).
사용 비율은 서버가 반환한 백분율을 사용하며, `TIME_LIMIT` 항목은 월간 웹 검색 횟수.
초기화 시각은 제공된 경우 epoch 밀리초로 해석하며, 없는 시각을 임의로 생성하지 않음.
필수 사용량 값이 누락되면 0으로 표시하지 않고 유효하지 않은 응답으로 보고.
같은 미터에 해당하는 크레딧·토큰 항목의 값과 기간이 같으면 한 번만 표시.
사용 비율·기간·초기화 시각이 서로 다르면 임의로 선택하지 않고 오류로 처리하여 마지막 정상 값 유지.

## 문제 해결

- **"No Z.ai API key"** — Customize → Z.ai → API Key에 키 추가.
  환경 변수를 사용하면 위 설정 절차에 따라 앱 재실행.
- **"Z.ai API key invalid"** — 키 거부(401/403).
  [Z.ai 콘솔](https://z.ai/manage-apikey/apikey-list)에서 다시 생성.
- **"No active GLM Coding Plan"**(이름 옆 황색 안내) — 키는 유효하지만 계정에 GLM Coding Plan이 없어 측정할 항목이 없는 상태.
  [z.ai/subscribe](https://z.ai/subscribe)에서 구독하면 요금제 활성화 후 사용량 표시.
- **미터에 "No usage data" 표시** — 요금제가 있지만 할당량 엔드포인트에서 아직 사용 가능한 한도를 반환하지 않은 상태.
  [요금제](https://z.ai/manage-apikey/coding-plan/personal/my-plan) 확인.
