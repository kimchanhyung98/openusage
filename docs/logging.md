# 로깅

OpenUsage는 문제 진단과 지원 요청에 사용할 파일 로그 기록.
선택한 레벨의 기록은 파일 로그와 macOS 통합 로그에 함께 전달.
Debug 기록을 확인하려면 앱의 로그 레벨과 통합 로그 조회 명령에서 모두 Debug 활성화 필요.
조회 명령은 [디버깅](/docs/debugging.md) 참조.

## 로그 파일 위치

```
~/Library/Logs/OpenUsage/OpenUsage.log
```

**Settings → Advanced**에서 다음 동작 사용 가능:

- **Copy Log Path** — 로그 파일 경로를 클립보드에 복사.
- **Reveal in Finder** — Finder에서 로그 파일 선택.

## 로그 레벨 변경

**Settings → Advanced → Log Level**에서 기록할 상세 수준 선택.
변경은 즉시 적용되며 재시작 불필요.
선택한 값은 앱을 다시 실행해도 유지.

| 레벨 | 캡처 내용 |
|---|---|
| Error | 실패만. |
| Warning | Error 기록과 경고. 일부 데이터 읽기 실패·부분 실패·지연 등 포함. |
| Info | Warning 기록과 일반 동작. 새로 고침 시작·종료, 프로바이더별 결과, 주요 캐시·인증 처리 포함. |
| Debug | Info 기록과 요청별·캐시 확인별 상세 정보. |

릴리스 기본값은 **Info**.
Warning은 문제의 복구 완료를 뜻하지 않음.
**Debug**는 기록량이 많으므로 상세 진단이 필요한 동안 사용.

## 오류와 지연 기록

### 로컬 사용 기록 읽기 실패

로컬 사용량 로그가 있는데 읽을 수 없으면, OpenUsage는 경고를 한 번 쓰고 그 새로 고침에서는 해당 파일을 건너뜀.
같은 실패가 계속되면 매 새로 고침마다 경고를 반복하지 않음.
실제 읽기에 성공한 뒤 다시 실패할 때 재경고.
발견 후 사라진 파일을 포함해 파일 부재는 복구로 간주하지 않음.
파일에 사용 가능한 사용량 기록이 없어도 실제 읽기에 성공하면 복구로 간주.
OpenCode 디렉터리 읽기 실패 후 데이터베이스를 다시 발견하면, 데이터베이스 읽기 결과와 함께 복구 여부 판정.
데이터베이스 읽기 실패가 남아 있으면 실패 상태 유지.
빈 데이터베이스 목록만으로 디렉터리 복구를 확정하지 않음.
발견 후 사라진 OpenCode 데이터베이스는 읽기 불가로 처리.
읽을 수 있는 데이터베이스가 하나도 없으면 사용량을 0으로 표시하지 않고 새로 고침 실패.

### 작업 진단

공통 진단 모듈은 보고받은 실패마다 로컬 기록 한 번 생성.
작업 실패는 Error로 기록.
선택 단계가 실패했어도 주요 결과를 사용할 수 있으면 Warning으로 기록.
이 기록에는 고정 작업명·오류 범주와 제공된 로컬 맥락 또는 오류 도메인·코드 포함.
원문 오류 설명은 이 진단 기록에서 제외.

주요 오류 범주:

- 터미널 보조 도구의 셸 실패: `subprocess`.
- 승인 거부: `permission`.
- 분류하지 못한 실패: `other`.
- 저장된 계정 인증 데이터 손상: `auth_invalid`.
- 키체인 접근 실패: `credential_access`.
- 업데이트 다운로드의 네트워크 실패: `network`.
  Sparkle 다운로드 오류에 포함되어도 같은 범주 유지.
- 사용할 수 없는 가격 피드 JSON 구조: `decoding`.
- 사용 가능한 캐시 없이 받은 가격 보충 파일의 304 응답: `decoding`.
  다음 조회는 조건부 요청 헤더 없이 실행.

다운로드 취소가 Sparkle 다운로드 오류에 포함되어도 취소 상태 유지.
일반적인 미로그인·지원하지 않는 요금제·아직 투표가 없는 Reset Watch 결과는 Info로 기록.
사용자 취소는 실패로 취급하지 않음.
HTTP 전송 상세는 Debug로 기록.
요청 실패를 처리하는 작업에서 최종 오류나 부분 실패 경고 기록.

### 느린 조회와 시간 초과

10초 이상 걸리는 프로바이더 새로 고침은 프로바이더 ID, 경과 밀리초, 임계값이 담긴 Warning 레벨 `[refresh]` 줄을 기록.
기본 Info 설정에서도 이 경고 확인 가능.
다른 프로바이더 카드는 독립적으로 갱신.
시스템 잠자기를 제외한 2분 안에 끝나지 않은 조회는 Error 레벨 `[refresh]` 시간 초과로 기록.
시간 초과는 `network` 범주의 갱신 실패 한 번으로 집계.
사용자 취소·계정 변경으로 폐기된 결과는 시간 초과 실패로 집계하지 않음.
동기 보조 명령의 제한 시간은 프로세스 종료와 출력 수집에 함께 적용.
명령 종료 뒤 자손이 출력 파이프를 계속 보유하면 제한 시간에 읽기를 종료하고 시간 초과 오류 반환.

## 서브시스템 태그

앱 로그 줄에는 검색용 대괄호 태그 포함:

`[refresh]` `[cache]` `[http]` `[auth]` `[keychain]` `[menubar]` `[updates]` `[config]` `[subprocess]` `[localapi]`, 그리고 `[plugin:claude]`, `[auth:claude]` 같은 프로바이더별 태그.

예를 들어 새로 고침 주기만 따라가려면:

```sh
grep '\[refresh\]' ~/Library/Logs/OpenUsage/OpenUsage.log
```

## 민감 정보 마스킹

일반 로그 메시지는 알려진 토큰 형식·계정 표시 형식·로컬 절대 경로를 기록 전에 마스킹.
URL과 HTTP 응답 본문은 별도 처리로 지정된 민감 매개변수·필드도 마스킹.
이 처리는 정해진 패턴을 대상으로 하므로 모든 임의의 비밀 값을 자동 식별하는 기능은 아님.
마스킹 대상 값이 12자 이하면 `[REDACTED]`로 치환.
더 긴 값은 `first4...last4`처럼 앞뒤 네 글자 유지.
인식한 로컬 절대 경로는 `[PATH]`로 치환.

HTTP 오류 본문은 마스킹한 미리보기를 Debug 로그에 기록 가능.
마스킹 후 500바이트 이하면 본문 전체가 미리보기에 포함될 수 있음.
더 길면 500바이트를 기준으로 마지막 문자가 잘리지 않도록 축약한 뒤 원문 크기 안내 추가.
마지막 문자와 크기 안내 때문에 최종 문자열은 500바이트를 넘을 수 있음.
로컬 API 요청 로그는 고정 메서드·라우트 범주만 유지하며, 쿼리 문자열·계정별 경로·알 수 없는 요청 원문은 제외.
로컬 로그에는 진단용 계정 카드 식별자가 포함될 수 있음.
익명 진단 이벤트에 허용하는 데이터 범위는 아래와 같이 별도 제한.

## 익명 진단 이벤트

**Share Anonymous Usage**가 켜져 있으면 프로바이더 결과와 일부 기능 작업도 구조화된 PostHog 이벤트로 전달.
로컬 로그 레벨 변경은 공유 동의 설정이나 이벤트 내용에 영향 없음.
작업 진단 이벤트는 고정 작업명·결과 및 오류 범주·프로바이더 계열·날짜·버전·빌드 채널·횟수만 허용.
원본 로그 줄·로컬 맥락·오류 도메인 및 코드·계정 ID·명령 출력·사용량 값 제외.
실행 시 공유가 이미 켜져 있으면 iCloud 기기 신원 초기화보다 먼저 진단 수집을 시작해 해당 오류도 집계.

프로바이더 요약에서 명시적인 수동 새로 고침과 계정 변경·인증 변경·재설정 크레딧 사용·정기 작업 구분.
한도 갱신에는 성공했지만 사용 기록 수집이나 선택 엔드포인트를 사용할 수 없다고 프로바이더가 알리면 부분 실패로 기록.
Codex 재설정 크레딧 응답이 잘못됐으면 사용량 응답의 대체 값을 유지하고 `decoding` 부분 실패로 기록.
Cursor의 요청 기반 대체 조회가 실패하면 HTTP·`network`·`decoding` 원인 범주 유지.
성공한 대체 조회도 별도 집계.
iCloud 읽기가 완료될 때 다른 기기 파일의 오류를 범주별로 한 번씩 기록.
중단·재시작된 동기화의 결과는 집계에서 제외.
범주별 첫 예상 외 실패·부분 실패·복구는 즉시 전송 대상.
즉시 전송은 현지 날짜 기준 하루 최대 30개로 제한.
기록된 모든 결과는 일일 횟수 집계에 포함.
복구 이벤트는 계정 신원에 종속되지 않는 작업으로 제한.
한 계정의 갱신 성공을 다른 계정의 장애 해소로 판정하지 않음.
Claude·Codex·Cursor는 토큰 갱신 요청·응답 검증 결과와 갱신된 인증 저장 결과를 각각 기록.
Claude 인증이 조건부 저장 전에 바뀌면 저장 결과를 계정 연결 변경으로 기록.
이때 기존 인증 재읽기 동작 유지.
Claude 로그인이 교체되면 이전 실패 진단을 보존하고 새 결과를 별도로 평가.
같은 로그인에서 대체 인증을 사용해도 해결되지 않은 저장 부분 실패는 유지.
토큰 갱신·인증 저장은 계정 간 복구 알림을 생성하지 않음.
일일 확인은 새로 고침 작업 전과 독립적인 1분 타이머에서 실행.
새로 고침 루프 취소 시 계정 동기화 대기 중에도 해당 타이머 중단.

PostHog 전송 로그에는 고정 엔드포인트 범주·HTTP 상태 또는 전송 오류 코드만 기록.
요청 본문·토큰·URL 제외.
HTTP 성공은 수집 서버가 요청에 응답했다는 의미.
대시보드 이벤트 표시나 크래시 심볼 해석 완료 여부는 별도 확인 필요.
동의·큐 삭제·크래시 핸들러 제한은 [개인정보 및 사용 데이터](/docs/privacy.md) 참조.

## 파일 크기 제한

로그 파일 교체 기준은 10 MB.
새 줄 추가로 기준을 넘게 되면 현재 파일을 `OpenUsage.1.log`로 옮기고 새 `OpenUsage.log`에 기록.
아카이브는 하나만 유지하므로 일반적인 파일 두 개의 합계는 약 20 MB.
이 기준은 파일 교체 시점이며, 개별 로그 줄의 길이를 자르는 상한은 아님.
이전 실행에서 남은 파일이 기준을 넘으면 시작 시 한 번 교체.
앱과 CLI는 공용 파일 잠금으로 기록·파일 교체를 조정해 서로의 줄을 덮어쓰지 않음.

> 참고: 개발 빌드와 릴리스 빌드는 같은 `OpenUsage.log`에 기록.
> 동시에 실행하면 두 빌드의 로그 줄이 같은 파일에 포함.
