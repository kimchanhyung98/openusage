# 새로 고침 및 캐싱

## 데이터가 업데이트되는 때

- 활성화된 모든 프로바이더가 함께 새로 고침됩니다. 앱을 실행할 때 한 번, 그 후 5분마다입니다(주기는 고정되어 있고 설정으로 바꿀 수 없습니다). 팝오버를 열어도 별도의 자동 새로 고침은 시작되지 않습니다. 프로바이더는 병렬로 조회하므로 빠른 카드가 느린 카드를 기다릴 필요는 없습니다. 다만 배치는 모든 프로바이더가 응답해야 끝나며, 알림·기록 동기화·다음 5분 대기는 배치가 끝난 뒤 시작됩니다.
- 프로바이더를 켜면(Customize에서 직접 켜거나 첫 실행/새 프로바이더 감지로 자동 활성화된 경우) 다음 주기를 기다리지 않고 바로 조회합니다. 이미 새로 고침이 진행 중일 때 켜도 마찬가지입니다.
- 대시보드와 설정 푸터에는 `Next update in Nm`이 표시됩니다. **이를 클릭하거나(푸터가 표시된 상태에서) ⌘R을 눌러** 캐시 없이 즉시 새로 고침할 수 있습니다.
- 1회 실행 명령 `openusage`는 이 영속 캐시를 사용해 5분 이내의 값을 재사용하고, 없거나 오래된 항목만 앱을 실행하지 않은 채 새로 고친 뒤 종료합니다. `openusage --force`는 캐시 나이와 관계없이 ⌘R과 같은 강제 새로 고침을 실행합니다.
- 프로바이더를 조회하는 동안 이름 옆에 작은 스피너가 표시되고, 푸터의 카운트다운 옆에도 스피너가 표시됩니다. 따라서 조회가 진행 중인지 값이 오래된 것인지 알 수 있습니다.
- [iCloud 동기화](icloud-sync.md)가 켜져 있으면 전체 배치가 끝난 뒤 Mac별 기록 파일을 한 번 씁니다. 프로바이더를 수동으로 새로 고치면 해당 프로바이더가 끝난 뒤 기록하고, 짧은 시간 안의 연속 변경은 한 번의 쓰기로 합칩니다.

## 캐싱

스냅샷은 디스크에 캐시되어 실행 시 바로 로드됩니다. 첫 조회가 끝나기 전에도 플레이스홀더 대신
마지막으로 확인된 값을 볼 수 있습니다.

Claude와 Codex 캐시 항목은 어떤 계정이 생성했는지도 기억합니다. 두 번의 실행 사이에 프로바이더의 기본 홈에 로그인된 계정을 바꾸면, 다음 실행 시 이전 계정의 캐시 값은 폐기되고(카드는 비어 있는 상태로 시작해 첫 가져오기로 채워집니다), 새 로그인 아래에서 이전 계정의 한도와 요금제가 잠깐 표시되는 일이 없습니다.

캐시된 값은 **현재 실행 중인 세션에서** 가져온 경우에만 *최신 값*으로 간주되어 다음 새로 고침을
건너뛸 수 있습니다. 따라서 이전 세션에서 만든 캐시는 실행 후 첫 번째 순회에서 반드시 다시 조회합니다.
값 자체는 즉시 표시하지만, 실시간 값을 얻기 위해 이전 캐시의 주기가 끝날 때까지 기다리지는 않습니다.
업데이트 직후에도 새 버전이 이전 버전의 데이터를 오래 보여 주지 않고 바로 새로 고치는 이유입니다.
현재 세션에서 새로 조회한 값은 다음 순회 전까지 한 주기 동안 최신으로 취급됩니다.

Claude, Codex, pi의 지출 기록에는 `~/Library/Application Support/OpenUsage/log-scan-cache/` 아래에
별도의 로컬 로그 파싱 캐시가 있습니다. 모델 가격을 적용하기 전의 파싱된 사용 이벤트를 저장하므로,
가격이 바뀌어도 변경되지 않은 JSONL을 다시 읽을 필요가 없습니다. 다시 실행했을 때는 경로, 크기,
수정 시각, 파서 버전이 모두 일치할 때만 항목을 재사용합니다. 같은 홈을 사용하는 카드는 파싱된
데이터를 공유하고, 소스 파일이 하나 바뀌면 그 파일의 레코드만 다시 씁니다. 기록 기간이 지나면
오래된 파일이 캐시에서 제거되고, 35일 동안 사용하지 않은 식별자도 삭제됩니다. 앱의 캐시 쓰기는
새로 고침이 끝날 때까지 모아서 처리하며, 1회 실행 CLI는 종료 전에 대기 중인 쓰기를 모두 처리합니다.

## 가져오기에 실패한 경우

새로 고침에 실패해도 **데이터는 지워지지 않습니다**. 마지막으로 정상적으로 가져온 값이 화면에
남고, 프로바이더 이름 옆에 작은 경고 삼각형이 표시됩니다. 마우스를 올리면 오류 메시지(예: "Not logged in"(로그인되지 않음))를 볼 수 있습니다. 다음 새로 고침이 성공하면 오류 표시가 사라집니다.

마지막으로 정상이었던 정규화 기록도 그대로 유지되므로, 일시적인 프로바이더 장애(또는 로컬 로그 스캔을 일시적으로 사용할 수 없는 상태에서 성공한 한도 새로 고침)가 iCloud 합산 지출 총액에서 이 Mac의 이전 기여분을 제거하지 않습니다.

한 번도 데이터를 가져오지 못한 행에는 임의의 숫자를 표시하지 않고 "No data"(데이터 없음)를 표시합니다.

## 오래된 데이터

실패한 새로 고침은 마지막 정상 값을 화면에 유지하므로, 새로 고침이 계속 실패하면 그 값이 그대로 남을 수 있습니다. 프로바이더 측에서 요금제나 한도가 바뀌었는데도 이전 숫자가 무한정 표시될 수 있다는 뜻입니다. 이를 분명히 알리기 위해, 데이터가 두 번의 새로 고침 주기(약 10분)보다 오래되면 프로바이더 이름 옆에 작은 **"Outdated"**(오래됨) 태그가 나타납니다. 마우스를 올리면 정확한 경과 시간("Last updated 3h ago"(마지막 업데이트: 3시간 전))을 볼 수 있습니다. 태그는 긴 요금제 이름을 밀어내지 않도록 짧게 유지됩니다. 이 태그가 보이면 아래 숫자는 실시간이 아니라 그 이전 시점의 값입니다. 보통 프로바이더가 새로 고침에 실패하고 있거나(경고 삼각형을 확인하세요) Mac이 잠자기 상태였기 때문입니다. 새로 고침에 성공하면 사라집니다.
