# 로깅

OpenUsage는 문제가 생겼을 때 앱의 동작을 확인해 지원팀과 공유할 수 있도록 파일 로그를
남깁니다. 선택한 레벨 이상의 로그는 macOS 통합 로그에도 기록됩니다. 따라서 레벨을 Debug로
올리면 두 로그 모두에서 더 자세한 정보를 볼 수 있습니다(`log stream`은 [디버깅](debugging.md) 참조).

## 로그 파일 위치

```
~/Library/Logs/OpenUsage/OpenUsage.log
```

가장 쉽게 가져오는 방법은 **Settings → Advanced**(설정 → 고급)에서 **Copy Log Path**(로그 경로 복사)로
경로를 복사하거나, **Reveal in Finder**(Finder에서 보기)로 Finder에서 파일을 선택하는 것입니다.
터미널을 사용할 필요는 없습니다.

## 로그 레벨 변경(Settings → Advanced)

**Log Level**(로그 레벨) 선택기로 기록할 상세 수준을 정합니다. 선택은 앱을 다시 실행해도 유지되며
즉시 적용됩니다. 재시작할 필요가 없습니다.

| 레벨 | 캡처 내용 |
|---|---|
| Error | 실패만 기록합니다. |
| Warning | 실패와 함께, 문제가 있었지만 복구된 항목도 기록합니다. |
| Info | 일반적인 흐름: 새로 고침 시작/종료, 프로바이더별 결과, 캐시 및 인증 마일스톤. |
| Debug | 요청별, 캐시 확인별 상세 정보를 포함한 모든 것. |

릴리스 기본값은 조용하면서도 충분한 **Info**입니다. **Debug**는 훨씬 많은 내용을 기록하므로
문제를 재현할 때만 켜세요.

로컬 사용량 로그가 있지만 읽을 수 없는 경우, OpenUsage는 경고를 한 번 남기고 해당 새로 고침에서는
그 파일을 건너뜁니다. 5분마다 같은 경고를 반복하지 않고, 파일을 다시 읽을 수 있게 되었다가
나중에 또 읽지 못하게 될 때만 다시 경고합니다.

10초 이상 걸리는 프로바이더 새로 고침은 프로바이더 ID, 경과 시간(밀리초), 임계값이 포함된 Warning 레벨
`[refresh]` 라인을 기록합니다. 기본 Info 설정에서도 보이므로, 느린 로컬 로그 스캔이나 네트워크 호출을
Debug를 켜고 재현하지 않아도 일반 지원 로그에서 식별할 수 있습니다. 이 경고는 진단용일 뿐이며, 다른
프로바이더 카드는 계속 독립적으로 갱신되고 느린 프로바이더도 끝까지 완료됩니다.

## 서브시스템 태그

모든 로그 줄에는 검색하기 쉽도록 대괄호 태그가 접두사로 붙습니다:

`[refresh]` `[cache]` `[http]` `[auth]` `[keychain]` `[menubar]` `[updates]` `[config]`
`[subprocess]` `[localapi]`, 그리고 `[plugin:claude]`, `[auth:claude]` 같은 프로바이더별 태그가
붙습니다.

예를 들어 새로 고침 주기만 따라가려면:

```sh
grep '\[refresh\]' ~/Library/Logs/OpenUsage/OpenUsage.log
```

## 절대 기록되지 않는 것

비밀 값은 로그에 절대 기록되지 않습니다. 액세스 토큰·리프레시 토큰·쿠키·세션 토큰·API 키는 로그 줄이
기록되기 전에 마스킹되고(민감한 값은 `first4...last4` 형태가 되며, 안전하게 마스킹하기에 너무 짧으면
`[REDACTED]`가 됩니다), 홈 디렉터리 아래의 파일시스템 경로는 `[PATH]`로 바뀝니다. 응답 본문은 전체가
기록되지 않으며, HTTP 오류 시에는 진단을 돕기 위해 동일한 마스킹을 먼저 거친, 마스킹되고 잘린(500바이트 이하)
미리보기를 Debug 레벨에서 기록할 수 있습니다. 마스킹 규칙은 원본 앱과 일치하며, 테스트
스위트가 이를 검증합니다.

## 파일 크기 제한

로그 파일은 약 10MB로 제한됩니다. 가득 차면 현재 파일이 `OpenUsage.1.log`로 교체되고 새 `OpenUsage.log`가
시작되므로, 오래 실행되는 세션이 디스크를 가득 채울 일은 없습니다(활성 파일과 아카이브 하나를 합쳐 최대
~20MB). 이전 세션에서 남은 초대형 파일은 실행 시 한 번 로테이션됩니다.

> 참고: 개발 빌드와 릴리스 빌드는 모두 같은 `OpenUsage.log`에 기록합니다. 동시에 실행하면 라인이
> 뒤섞입니다. 일반 사용에는 문제없지만, 둘을 동시에 디버깅한다면 알아 둘 만합니다.
