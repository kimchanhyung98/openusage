# 로깅

OpenUsage는 앱이 무엇을 하고 있었는지 캡처해 문제가 생겼을 때 지원팀과 공유할 수 있도록 파일 로그를 유지.
선택한 레벨 이상의 줄은 macOS 통합 로그에도 들어가므로, 레벨을 Debug로 올리면 양쪽 모두에서 추가 상세 정보를 확인 가능(`log stream`은 [디버깅](debugging.md) 참조).

## 로그 파일 위치

```
~/Library/Logs/OpenUsage/OpenUsage.log
```

가장 쉬운 방법은 Settings -> Advanced(설정 -> 고급)를 열고 **Copy Log Path**(로그 경로 복사, 경로를 클립보드에 복사)나 **Reveal in Finder**(Finder에서 보기, Finder 창에서 파일 선택)를 쓰는 것.
터미널은 필요 없음.

## 로그 레벨 변경(Settings -> Advanced)

**Log Level**(로그 레벨) 선택기가 기록할 상세 수준을 결정.
선택은 앱을 다시 실행해도 유지되고 즉시 적용 — 재시작 불필요.

| 레벨 | 캡처 내용 |
|---|---|
| Error | 실패만. |
| Warning | 실패에 더해, 문제로 보였지만 복구된 상황까지. |
| Info | 일반적인 흐름: 새로 고침 시작/종료, 프로바이더별 결과, 캐시·인증 마일스톤. |
| Debug | 요청별·캐시 확인별 상세 정보까지 전부. |

릴리스 기본값은 **Info** — 조용하면서도 필요한 건 남기는 수준.
**Debug**는 선택 사항이며 훨씬 시끄럽기 때문에 문제를 재현하는 동안에만 켜기.

로컬 사용량 로그가 있는데 읽을 수 없으면, OpenUsage는 경고를 한 번 쓰고 그 새로 고침에서는 해당 파일을 건너뜀.
5분마다 같은 경고를 반복하지 않고, 실제 읽기 성공을 확인한 뒤 다시 읽기 실패가 발생할 때만 재경고.
파일 부재는 복구로 간주하지 않음.
공통 진단 모듈은 보고된 실패마다 로컬 기록을 한 번 생성: 작업 실패는 Error, 선택 단계가 실패해도 주요 결과를 사용할 수 있으면 Warning.
고정 작업명·오류 범주와 제공된 로컬 맥락 또는 오류 domain·code를 포함하며, 원문 오류 설명은 제외.
터미널 helper의 셸 실패는 subprocess, 승인 거부는 permission, 미확인 실패는 other로 분류.
업데이트 다운로드의 네트워크 실패는 Sparkle 다운로드 오류에 포함되어도 network를 유지하며, 사용할 수 없는 가격 feed JSON 구조는 decoding으로 분류.
다운로드 취소가 Sparkle 다운로드 오류에 포함되어도 취소 상태 유지.
일반적인 미로그인·지원하지 않는 요금제·아직 투표가 없는 Reset Watch 결과는 Info 유지, 사용자 취소는 실패로 취급하지 않음.
HTTP 전송 상세는 Debug에 기록하고, 실패를 처리하는 작업에서 최종 오류나 부분 실패 경고 기록.

10초 이상 걸리는 프로바이더 새로 고침은 프로바이더 ID, 경과 밀리초, 임계값이 담긴 Warning 레벨 `[refresh]` 줄을 기록.
기본 Info 설정에서도 보이므로, 느린 로컬 로그 스캔이나 네트워크 호출을 Debug로 재현하지 않고 일반 지원 로그에서 바로 식별 가능.
이 경고는 진단용일 뿐 — 다른 프로바이더 카드는 계속 독립적으로 갱신되고, 느린 프로바이더도 끝까지 완료.

## 서브시스템 태그

모든 줄에는 grep하기 쉽도록 대괄호 태그가 접두사로 붙음:

`[refresh]` `[cache]` `[http]` `[auth]` `[keychain]` `[menubar]` `[updates]` `[config]` `[subprocess]` `[localapi]`, 그리고 `[plugin:claude]`, `[auth:claude]` 같은 프로바이더별 태그.

예를 들어 새로 고침 주기만 따라가려면:

```sh
grep '\[refresh\]' ~/Library/Logs/OpenUsage/OpenUsage.log
```

## 절대 기록되지 않는 것

비밀 값은 로그에 닿지 않음.
액세스·리프레시 토큰, 쿠키, 세션 토큰, API 키는 줄이 기록되기 전에 마스킹되고(민감한 값은 `first4...last4`, 안전하게 가리기에 너무 짧으면 `[REDACTED]`), 홈 디렉터리 아래 파일시스템 경로는 `[PATH]`로 치환.
응답 본문은 전체가 기록되는 일이 없고, HTTP 오류 시 진단을 돕기 위해 마스킹·절단된(500바이트 이하) 미리보기를 Debug에서 기록할 수 있으며 이 역시 같은 마스킹을 먼저 통과.
로컬 API 요청 로그는 고정 메서드·라우트 범주만 유지하며, 쿼리 문자열·계정별 경로·알 수 없는 요청 원문은 제외.
로컬 로그에는 진단용 계정 카드 식별자가 남을 수 있으며, 더 제한적인 익명 분석 payload와는 별개.

## 익명 진단 이벤트

**Share Anonymous Usage**가 켜져 있으면 프로바이더 결과와 일부 기능 작업도 구조화된 PostHog 이벤트로 전달.
로컬 로그 레벨 변경은 공유 동의 설정이나 이벤트 payload에 영향 없음.
이벤트는 고정 작업명·결과 및 오류 범주·프로바이더 family·날짜·버전·빌드 채널·횟수만 허용.
원본 로그 줄·로컬 맥락·오류 domain 및 code·계정 ID·명령 출력·사용량 값 제외.
실행 시 공유가 이미 켜져 있으면 iCloud 기기 신원 초기화보다 먼저 진단 수집을 시작해 해당 오류도 집계.

프로바이더 요약에서 명시적인 수동 새로 고침과 계정 변경·인증 변경·재설정 크레딧 사용·정기 작업 구분.
한도 갱신 성공 중 히스토리 스캔이나 선택 엔드포인트를 사용할 수 없다고 프로바이더가 알리면 부분 실패로 기록.
잘못된 Codex 재설정 크레딧 응답은 사용량 응답의 대체 값을 유지하며 decoding 부분 실패로 기록.
Cursor 요청 기반 대체 조회 실패는 HTTP·network·decoding 원인 범주를 유지하며 성공한 대체 조회도 집계.
iCloud 읽기 완료마다 다른 기기 파일의 각 오류 범주를 한 번씩 기록하며, 중단·재시작된 동기화의 결과는 집계에서 제외.
범주별 첫 예상 외 실패·부분 실패·복구는 즉시 전송 가능하며 현지 날짜 기준 하루 최대 30개로 제한; 기록된 모든 결과는 일일 횟수에 유지.
복구 이벤트는 계정 신원에 종속되지 않는 작업으로 제한; 한 계정의 갱신 성공을 다른 계정의 장애 해소로 판정하지 않음.
Claude·Codex·Cursor는 토큰 갱신 요청·응답 검증 결과와 갱신된 인증 저장 결과를 각각 기록.
Claude 인증이 조건부 저장 전에 바뀌면 저장 결과를 계정 바인딩 변경으로 기록하고 기존 재판독 동작 유지.
Claude 로그인 교체 시 이전 실패 진단은 보존하되 새 결과는 별도 평가; 같은 로그인 내 대체 인증 사용 시 해결되지 않은 저장 부분 실패 유지.
토큰 갱신·인증 저장은 계정 간 복구 알림을 생성하지 않음.
일일 확인은 새로 고침 작업 전과 독립적인 1분 타이머에서 실행.
새로 고침 루프 취소 시 계정 동기화 대기 중에도 해당 타이머 중단.

PostHog 전송 로그에는 고정 엔드포인트 범주·HTTP 상태 또는 전송 오류 코드만 기록하며 요청 본문·토큰·URL 제외.
HTTP 성공은 수집 서버 응답의 증거이며, 대시보드 이벤트 표시나 크래시 심볼 해석 완료의 증거는 아님.
동의·큐 삭제·크래시 핸들러 제한은 [개인정보 및 사용 데이터](/docs/ko/privacy.md) 참조.

## 파일 크기 제한

로그는 약 10MB로 제한.
가득 차면 현재 파일이 `OpenUsage.1.log`로 로테이션되고 새 `OpenUsage.log`가 시작되므로, 오래 실행되는 세션이 디스크를 채울 일은 없음(활성 파일과 아카이브 하나를 합쳐 최대 ~20MB).
이전 세션에서 남은 초대형 파일은 실행 시 한 번 로테이션.
독립 기록기는 공용 파일 잠금으로 추가 기록·로테이션을 조정하므로 앱과 CLI가 서로의 줄을 덮어쓰지 않음.

> 참고: 개발 빌드와 릴리스 빌드는 같은 `OpenUsage.log`에 기록.
> 동시에 실행하면 줄이 섞임 — 일반 사용에는 문제없지만 둘을 함께 디버깅한다면 알아 둘 만함.
