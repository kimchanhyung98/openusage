# 프로바이더 추가

OpenUsage에 새 AI 프로바이더를 추가하는 방법을 설명합니다. 아래 구성 요소가 어떻게 맞물리는지 이해하려면 먼저
[아키텍처 개요](architecture.md)를 읽어 보세요.

## 프로바이더란

프로바이더는 `Sources/OpenUsage/Providers/<Name>/` 아래에 두는, `ProviderRuntime`을 준수하는 작은
Swift 모듈입니다. 세 부분으로 구성됩니다:

- 사용자의 Mac에 이미 있는 인증 정보(설정 파일, 키체인)를 읽는 **인증 스토어**,
- 프로바이더의 API를 호출하는 **사용량 클라이언트**,
- 응답을 앱의 지표 어휘로 변환하는 **매퍼**입니다.

OpenUsage는 사용자에게 토큰을 붙여 넣으라고 요구하지 않습니다. 프로바이더 자체 CLI나 앱에 이미
로그인되어 있다면, OpenUsage는 그 기존 인증 정보를 읽습니다.

`refresh()` 외에도 모든 프로바이더는 `hasLocalCredentials()`를 구현합니다. 이 메서드는 파일과 키체인만
확인하는 저비용 로컬 검사이며 네트워크를 사용하지 않습니다. 새 설치에서는 이 검사를 한 번 실행해
사용자가 실제로 사용하는 프로바이더만 켭니다(`FirstRunSeeder` 참조). 기존 설치에서는 새 프로바이더가
추가된 뒤 첫 실행 때 한 번 실행합니다(`NewProviderSeeder` 참조). 따라서 이 메서드를 제대로 구현해야
해당 도구를 가진 사용자에게만 새 프로바이더가 자동으로 켜집니다([활성화되는 프로바이더](provider-enablement.md) 참조).
`refresh()`가 사용하는 것과 같은 인증 정보 출처를 확인하고, 블로킹 작업은 `loadOffMainActor`로 실행하세요.

## 지표 계약

`refresh()`는 `lines`에 `MetricLine` 값을 담은 `ProviderSnapshot`을 반환합니다. 어떤 프로바이더인지가
아니라 값의 형태에 따라 케이스를 선택하세요:

- **`.progress`** — `used`, `limit`, `format`을 가진 상한이 있는 미터입니다:
  - `.percent`는 할당량 형태의 한도(세션, 주간)에 사용하고,
  - `.dollars`는 상한이 있는 달러 금액(상한이 있는 크레딧)에 사용하고,
  - `.count(suffix:)`는 상한이 있는 횟수(예: 주기당 요청 수)에 사용합니다.
- 사용 기간이 특정 시각에 초기화된다면 `resetsAt`을 추가하고, 주기 길이에는 `periodDurationMs`를
    추가하세요.
- **`.values`** — 하나 이상의 원시 숫자(각각 `MetricValue`: 숫자, 종류, `"tokens"` 같은 선택적 단위
  레이블)를 담는 상한 없는 행입니다. 하루 지출은 달러 *와* 토큰을 함께 담고, Codex 크레딧은 달러
  *와* 개수를 함께 담듯이, 상한 없는 숫자 행에는 이 케이스를 사용하세요. 위젯은 디스크립터를
  통해 무엇을 보여 줄지(비용만, 토큰만, 둘 다) 선택하고, 포매팅은 표시 단계에서 이루어지므로 메뉴
  막대가 문자열을 다시 파싱할 일이 없습니다. 숫자에는 이 케이스를 우선하세요.
- **`.badge`** — `Disabled`나 종량제 상한처럼 짧은 상태를 표시합니다. 숫자보다 상태를
  나타낼 때 사용하세요.
- **`.chart`** — 컴팩트한 사용량 추이 행을 위한 날짜가 붙은 숫자 포인트입니다.
- **`.text`** — 로컬 API에 그대로 유지되는 문자열 값의 프로바이더 알림입니다. 위젯을 렌더링하지 않으므로,
  디스크립터 기반 행에는 모두 `.progress`, `.values`, `.badge`, `.chart`를 사용하세요.

프로바이더가 요금제 이름을 제공하면 스냅샷의 `plan`에 설정하세요. 실패하면 가능할 때 타입이 지정된
프로바이더 오류와 함께 `ProviderSnapshot.error(provider:error:)`를 반환하세요. 그러면 텔레메트리가
"not logged in"(로그인되지 않음)이나 "network"(네트워크)처럼 안정적이고 개인을 식별하지 않는
사유로 실패를 그룹화할 수 있게 하세요. 타입이 지정된 오류가 없을 때만 메시지 전용 팩토리를 사용하고,
오래되었거나 비어 있는 데이터를 조용히 반환하지 마세요.

## 단계

1. **먼저 확인하세요.** 열린 이슈와 `docs/providers/`를 살펴 해당 프로바이더가 이미 요청되었거나
   작업 중인지 확인하세요.
2. **모듈을 만드세요.** 인증 스토어, 사용량 클라이언트, 매퍼를 갖춰
   `Sources/OpenUsage/Providers/<Name>/`를 추가하고 `ProviderRuntime`을 준수하세요. `refresh()`와
   `hasLocalCredentials()` 둘 다 필요합니다(후자는 컴파일러가 강제하며 기본 구현이 없습니다).
   프로브는 로컬 전용으로 유지하고, `refresh()`가 시작할 때 사용하는 것과 같은 인증 스토어 로더와
   인증 정보 유효성 필터를 재사용하세요. 인증 정보를 읽는 별도 경로를 만들지 마세요.
   `Support/`의 공유 헬퍼(JSON/숫자/퍼센트 파싱용 `ProviderParse`, 타임스탬프용 `OpenUsageISO8601`)를
   복사하지 말고 재사용하세요.
3. **위젯을 선언하세요.** `WidgetDescriptor+Factories.swift`의 팩토리(`percent`, `boundedDollars`,
   `spend`, `tokenSpend`, `combined`, `values`, `badge` 등)를 사용해 프로바이더의 지표를
   `WidgetDescriptor`로 노출하세요.
4. **등록하세요.** `AppContainer`의 목록에 프로바이더를 추가하세요.
5. **테스트하세요.** 샘플 API 응답을 넣고 결과 지표 행을 검사하는 매퍼 테스트를 포함해,
   `Tests/OpenUsageTests/` 아래에 집중적인 테스트를 추가하세요.
6. **문서화하세요.** 추적 항목, 인증 정보 출처, 호출하는 엔드포인트, 오류 상태의 의미를 다루는
   페이지를 `docs/providers/` 아래에 추가하세요.
7. **실행하세요.** `./script/build_and_run.sh`로 빌드하고 실행해 프로바이더가 표시되는지 확인하세요.

## 컨벤션

- 경계(API 응답)에서만 검증하고 앱 내부 타입은 신뢰하세요.
- 숫자를 알아보기 쉽도록 프로바이더 자체 대시보드가 사용하는 지표 레이블과 단위에 맞추세요.
- 프로바이더의 **빠른 링크**는 `Provider` 값(`links:`)에 선언하세요. 각 링크는 카드의 확장 영역에
  버튼으로 렌더링되는 `ProviderLink(label:url:)`이며, 기본 브라우저에서 URL을 엽니다. 프로바이더 자체
  Status / Console / Dashboard 페이지가 있으면 포함하고, 없는 프로바이더는 `links`를 생략하세요
  (기본값은 비어 있음). 프로바이더당 링크는 최대 **두 개**로 제한하세요(표준 레이블: Status,
  Dashboard, API Keys, Usage). 레이블이 비어 있지 않은 `http(s)` URL만 렌더링됩니다.

## 사용자 제공 API 키

대부분의 프로바이더는 Mac에 이미 있는 인증 정보(연동 CLI/앱의 세션, 키체인)를 읽습니다.
로컬에서 읽을 것이 전혀 없는 프로바이더(OpenRouter가 첫 사례)는 `APIKeyManaging`을 준수해,
프로바이더별 UI 작업 없이 앱 내 **Settings → API Keys**(설정 → API 키) 카드가 키를 관리하도록 합니다:

- 인증 스토어는 네 가지 상태의 `keyStatus()`(`notSet` / `fromEnvironment` / `saved` /
  `overrideActive`), 표시 토글용 `currentAPIKey()`, 그리고 인증 스토어가 이미 읽는 설정 파일에 쓰는
  `saveAPIKey(_:)` / `deleteAPIKey()`를 노출합니다. 설정 파일이 환경 변수보다 우선하기 때문에 저장된
  키가 자동으로 오버라이드가 됩니다.
- 프로바이더는 이들을 인증 스토어에 위임하는 방식으로 준수하고, 카드 문구에 쓸 저장 경로와 환경
  변수 이름을 보고합니다.
- `AppContainer`는 모든 `APIKeyManaging` 프로바이더를 `apiKeyProviders`에 모으고, 카드가 이를
  나열합니다. 평소처럼 프로바이더를 레지스트리에 추가하면 카드가 자동으로 인식합니다.

키는 인증 스토어가 이미 확인하는 파일에 저장하세요(별도의 저장소를 도입하지 마세요). 그래야 그 파일이
기준 저장소로 남고 사용자가 직접 편집할 수도 있습니다.
