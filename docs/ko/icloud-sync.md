# iCloud 동기화

**Sync Across Macs**(Mac 간 동기화)는 기본적으로 꺼져 있습니다. 켜면 각 Mac이 버전이 지정된
OpenUsage 히스토리 파일 하나를 앱의 비공개 iCloud 컨테이너에 기록하고, 같은 iCloud 계정으로
로그인된 다른 Mac이 기록한 파일을 읽습니다. 임의의 기기 ID는 로그인 키체인에 보관되므로,
앱 환경 설정을 재설정하거나 앱을 재설치한 뒤에도 같은 Mac은 기존 파일을 계속 갱신합니다.
폴더 선택기, 페어링 코드, 별도의 계정은 없습니다.

이 파일에는 한 Mac에 로컬로 존재하는 소스(Claude, Codex, Grok, OpenCode)의 정규화된 일일 토큰과
지출, 모델별 합계, 알 수 없는 모델 이름이 담깁니다. 인증 정보, 계정 한도, 원시 로그,
프로바이더 응답은 포함하지 않습니다. Cursor의 히스토리는 이미 계정 전체에 걸쳐 있으므로
로컬에만 유지되며 Mac 간에 합산되지 않습니다. 프로바이더를 비활성화하면 해당 프로바이더의
피어 기여분이 결합 보기에서 즉시 제거되고 이 Mac의 다음 iCloud 기록에서도 빠지며, 로컬에
캐시된 스냅샷은 그대로 남습니다.

OpenUsage는 유효한 파일을 메모리에서 합쳐 Today, Yesterday, Last 30 Days, Usage Trend,
알 수 없는 모델 경고, 모델별 내역을 다시 계산합니다. 합쳐진 지출 행은 대시보드,
Total Spend(총 지출), 메뉴 막대 고정 항목, 공유 카드, 로컬 HTTP API에 공급됩니다.
`/v1/usage`와 `/v1/limits` 모두 같은 렌더링된 스냅샷을 읽습니다. 전자는 더 이상 권장되지 않는
UI 중심 형식이고 후자는 정규화된 형식입니다. 할당량, 요금제, 잔액, 프로바이더 오류는 이
스냅샷 안에서 이 Mac의 값으로 유지됩니다. 다른 Mac의 오래된 파일에 남아 있는 행도 로컬
기록 스캐너와 같은 달력 기간을 벗어나면 무시됩니다.

이 Mac은 5분 새로 고침 배치, 수동 새로 고침, 프로바이더 활성화 변경 후에 파일을 갱신합니다.
iCloud는 변경 사항을 즉시 전달하지 않을 수 있으므로, 특히 오프라인 상태에서는 다른 Mac이
파일을 받는 데 5분 이상 걸릴 수 있습니다. 다운로드된 변경 사항은 macOS가 알려 주는 즉시 다시 읽습니다.

## Mac 간 다중 계정

히스토리는 카드 이름이 아니라 **계정** 기준으로 매칭됩니다. 각 Mac의 파일은 모든 카드가 어느
계정에 속하는지(불투명한 계정/조직 식별자이며 이메일은 아님)를 기록하므로, 한 Mac에서는 메인
카드로, 다른 Mac에서는 추가 계정 카드로 표시되더라도 같은 계정은 어디서나 같은 카드로
병합됩니다.

다른 Mac에서는 사용하지만 이 Mac에서는 로그인하지 않은 계정은 카드로 만들지 않습니다. 대신
**Total Spend**에 계정 코드("claude@ab12cd34")라는 이름의 자체 조각으로 표시됩니다. 따라서
상단의 숫자에는 모든 Mac의 합계가 반영되고, 그런 계정이 여러 개여도 서로 구분할 수
있습니다. 이 코드는 해당 계정이 로그인된 모든 Mac에서 그 계정의 카드가 가지는 것과 같은
id입니다(동기화된 파일에는 라벨로 쓸 이메일이나 이름이 없습니다). 그 계정을 로컬에서
로그인하는 순간, 같은 id 아래에 모든 Mac의 기록이 이미 연결된 상태로 카드가
나타납니다.

이전 버전 OpenUsage를 실행하는 Mac은 자기 형식의 파일은 읽지만 이 Mac이 쓴 새 형식의 파일은
"update OpenUsage"로 표시합니다. 멀티 계정 환경을 동기화하려면 양쪽 Mac을 모두 업데이트하세요.

설정에는 유효한 각 기기 파일이 해당 Mac이 생성한 시각과 함께 나열됩니다. 결합 요약에서
Mac을 제거하려면 해당 Mac에서 동기화를 끄세요. 그러면 해당 Mac의 파일이 iCloud에서
삭제됩니다. 동기화를 끄면 그 Mac은 피어 읽기도 중단하고, 그곳의 모든 표시 영역이 즉시
로컬 전용 지출로 돌아갑니다. 형식이 잘못된 파일은 무시되며 설정과 앱 로그에 보고됩니다.

## 개발 및 릴리스 설정

Apple은 앱에 임베딩된 프로비저닝 프로파일에 iCloud 컨테이너 할당이 포함되어 있을 것을
요구합니다. OpenUsage는 개발 빌드가 프로덕션 히스토리를 쓸 수 없도록 별도의 리소스를
사용합니다:

- `com.kimchanhyung98.openusage.dev`는 `iCloud.com.kimchanhyung98.openusage.dev`를 사용합니다.
- `com.kimchanhyung98.openusage`는 `iCloud.com.kimchanhyung98.openusage`를 사용합니다.

등록된 모든 개발 Mac을 포함하는 `MAC_APP_DEVELOPMENT` 프로파일과 릴리스용
`MAC_APP_DIRECT` 프로파일을 생성하세요. 포함된 각 Mac에 개발 프로파일을 설치하세요.
개발 빌드는 Xcode의 현재 프로파일 디렉터리 또는 레거시 MobileDevice 디렉터리에서 개발
번들 및 iCloud 컨테이너와 일치하는, 만료되지 않은 가장 최신 프로파일을 자동으로 선택합니다:

```bash
./script/build_and_run.sh
```

자동 선택을 재정의해야 할 때만 `ICLOUD_PROVISIONING_PROFILE=/path/to/profile.mobileprovision`을
설정하세요. 명시한 경로가 존재하지 않으면 iCloud 접근 권한이 없는 앱을 조용히 만들어 내는
대신 빌드가 실패합니다.

릴리스 워크플로는 리포지토리 Actions 시크릿 `APPLE_DEVELOPER_ID_ICLOUD_PROFILE`에서 base64로
인코딩된 `MAC_APP_DIRECT` 프로파일을 읽습니다. 원본 프로비저닝 프로파일과 서명용 `.p12`는
리포지토리가 아니라 반드시 비밀번호 관리자에 보관하세요. 프로비저닝 프로파일에는 개인 키가
아니라 인증서와 권한(entitlements)이 들어 있지만, 서명 자산으로 취급하면 교체(rotation)를
예측 가능하게 유지할 수 있습니다.

실행 중인 빌드가 실제로 기록한 히스토리를 확인하려면 먼저 파일을 찾고, 파일이 존재할 때만
`jq`를 호출하세요:

```bash
file=$(find "$HOME/Library/Mobile Documents" \
  -type f -path '*openusage*/OpenUsage/History/v1/*.json' -print -quit)

if [[ -n "$file" ]]; then
  jq . "$file"
else
  echo "No OpenUsage iCloud history file found"
fi
```

동기화가 꺼져 있거나, 앱이 일치하는 프로파일 없이 서명되었거나, 첫 쓰기가 아직 완료되지 않은
경우에는 파일이 없는 것이 정상입니다. 설정 오류와 앱 로그가 이 경우들을 구분해 보여 주며,
스피너는 iCloud 읽기 또는 쓰기가 실제로 진행 중일 때만 나타납니다.
