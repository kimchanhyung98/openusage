# 설정

설정은 팝오버 안에 있음 — 별도 창 없음.
푸터의 **Options** 메뉴 · 팝오버가 열린 상태의 ⌘, 단축키 · 메뉴 막대 아이콘 우클릭 후 Settings 선택 중 하나로 열기.
대시보드가 옆으로 밀리며 설정 화면으로 전환되고, 왼쪽 위에 뒤로 가기 버튼 표시.
해당 버튼, ⌘, 단축키, Esc로 대시보드에 복귀(Esc는 항상 대시보드로 먼저 돌아가며, 한 번 더 누르면 팝오버 닫기).

## 일반

| 설정 | 옵션 | 동작 |
|---|---|---|
| Show Total Spend(총 지출 표시) | 켜기/끄기 | 프로바이더를 합산한 [총 지출](/docs/dashboard.md#총-지출) 카드를 대시보드 상단에 표시할지 여부.<br>기본값은 켜기이며, 지출을 추적하는 프로바이더(Claude, Codex, Cursor, Grok, OpenCode)가 하나라도 활성화되어 있으면 카드 등장. |
| Launch at Login(로그인 시 실행) | 켜기/끄기 | 앱을 로그인 항목으로 등록(시스템의 로그인 항목 레지스트리가 기준). |
| Global Shortcut(전역 단축키) | 단축키 기록 | 어디서든 팝오버를 토글하는 전역 단축키.<br>필드를 클릭하고 조합키 입력, ⓧ를 누르면 지워지고 단축키 비활성. |

**레거시(0.7 이전) 에디션에서 업그레이드하는 경우:** 예전 에디션은 자체 런처 파일로 로그인 시 실행을 관리했고, 덮어쓰기 업데이트는 그 파일을 그대로 남겨 둠.
남은 파일 때문에 로그인할 때마다 앱이 두 번 실행될 수 있었고, 시스템 설정 → 로그인 항목에는 OpenUsage가 아닌 서명 회사명으로 표시.
현재는 실행 시 해당 파일이 OpenUsage를 가리키는지 확인한 뒤에만 자동 제거 — 로그인 시 위 Launch at Login 토글이 관리하는 앱 하나만 실행.

## 계정

Accounts 섹션에서 Claude와 Codex 계정 관리.
계정은 프로바이더 로그인을 저장하는 사용자 이름 레코드 — 고를 폴더도, 편집할 경로도 없음.
기존 `~/.claude`와 `~/.codex` 설정(MCP 설정, 메모리, 플러그인, 스킬, 세션 기록)은 항상 그대로.
계정 전환은 새 터미널 세션이 쓰는 로그인만 교체.

`alpha`, `beta` 같은 계정명은 사용자가 관리하는 로컬 제목이며 이메일 주소나 영구 프로바이더 신원이 아님.
검증된 재로그인은 해당 계정명에 현재 저장된 프로바이더 신원과 인증 정보를 교체 가능.
따라서 두 계정명에 같은 프로바이더 신원의 인증 정보가 일시적으로 저장될 수 있으며, 관리형 레코드는 프로바이더 신원이 아니라 계정명으로 구분.
예를 들어 `beta`를 `gamma`로 이름 변경한 뒤 그 계정에서 재로그인하거나, `alpha`를 선택해 기존 `beta`에 저장된 프로바이더 계정으로 로그인한 뒤 예전 `beta` 레코드 제거 가능.

- 추가(+) 버튼으로 계정 추가 흐름 열기.
  이미 로그인된 상태이고 등록된 계정이 아직 없으면 현재 로그인을 바로 가져옴 — 새 브라우저 로그인 없음.
  그 외에는 공식 Claude 또는 Codex 로그인 열림.
  추가 계정은 OpenUsage 소유의 비공개 작업 공간 안에서 로그인하므로, 로그인 중에도 현재 계정과 열려 있는 터미널은 계속 동작.
  로그인을 취소하거나 실패하면 아무것도 등록되지 않음.
- 계정별 인증 정보는 macOS Keychain의 비공개 스냅샷으로 보관.
  **Ready**는 사용 가능한 저장 로그인과 현재 앱 실행 중 성공한 사용량 확인이 필요하며, 남아 있는 오류나 경고가 없어야 표시.
  **Session Expired**는 토큰 갱신에서 세션 만료가 확인된 상태 — 만료된 액세스 토큰·폐기된 토큰·충돌한 토큰은 **Sign-In Needed**.
  **Refresh Failed**는 연결·서버·사용량 확인 문제이며 세션 만료로 취급하지 않음.
  사용량 조회가 시스템 잠자기를 제외한 2분 안에 끝나지 않은 경우도 **Refresh Failed** — 이전 조회가 종료된 뒤 재시도 가능.
  저장 로그인 확인 중에는 **Checking**, 로컬 확인 후 사용량 조회 전이나 재로그인 직후에는 **Not Checked** 표시.
  이미 확인된 **Session Expired**·**Sign-In Needed**는 로컬 재확인 중이거나 Keychain 접근에 실패해도 유지하며, 재로그인으로 인증 정보가 바뀌면 해제.
  재로그인하면 이전 인증 경고를 지우고, 새 확인 중에도 마지막 사용량 유지.
  저장된 로그인 부재·데이터 손상·신원 불일치는 **Sign-In Needed**.
  Keychain 잠금·접근 승인 대기로 저장 로그인을 읽지 못하면 **Refresh Failed**로 안내하며, 계정 전환을 통한 승인 재시도 허용.
  해당 계정의 새로 고침이 끝나면 읽기에 실패했던 저장 로그인을 다시 확인 — 승인 후 Settings를 다시 열지 않아도 상태 갱신.
  저장 로그인 확인은 화면 조작을 막지 않도록 백그라운드에서 실행하며, 화면 종료 또는 계정·선택·인증 변경 시 이전 결과 폐기.
  계정 행과 Manage 화면은 같은 계정의 대시보드 갱신 결과를 반영하며, Settings가 열린 동안에도 갱신.
  과거 사용량은 **Outdated**와 함께 남을 수 있지만, 해당 캐시를 읽는 것만으로 오류를 해제하거나 **Ready**로 판정하지 않음.
  선택된 Claude 계정은 공유 `~/.claude` 홈의 로그인도 사용 가능하고 해당 계정명에 현재 저장된 신원과 일치해야 함.
- 한 프로바이더에 계정이 둘 이상이면 각 행에 새 터미널 세션이 쓸 계정을 고르는 토글 추가.
  전환은 확인 요청하며, 확인 버튼은 **Use {Provider}: {account_name}**으로 대상 프로바이더와 계정명 표시.
  **Separate Cards**에서는 대시보드 카드 제목·지표 행의 우클릭 메뉴에서도 같은 전환 가능.
  전환 전·후 계정의 인증 처리와 후속 사용량 갱신·주간 타이머 처리가 끝날 때까지 다음 계정 전환 차단.
  다른 계정의 사용량 갱신·주간 타이머는 대기 대상에서 제외.
  이미 시작된 외부 로그인 반영은 공유 계정 목록 갱신이 끝날 때까지 먼저 대기.
  조회 오류가 표시되더라도 남은 작업이 종료된 뒤 다시 전환 가능.
  전환 전에 시작한 새로 고침의 인증 반영 오류는 전환 후 계정에 표시하지 않음.
  전환 중에는 계정 추가·관리 열기·재로그인·제거와 계정 사용량의 수동 새로 고침도 잠시 차단.
  Settings 재진입으로 시작되는 외부 로그인 반영도 전환 종료 전까지 생략.
  승인하면 공유되는 Claude 또는 Codex 설정 홈 하나는 그대로 두고, 그 인증 정보만 선택 계정으로 교체.
  교체 후 선택한 계정의 신원과 일치하는지 검증.
  적용이나 검증에 실패하고 이전 인증 정보가 있으면 해당 정보로 복원 시도.
  복원 자체가 실패할 수도 있으며, 이 경우 앱 로그에 복원 실패 기록.
  승인 시 로그인 셸 시작 파일(zsh 또는 fish)에 작은 `claude`/`codex` 함수도 설치·갱신하므로, 새 터미널 세션이 전환을 따라감.
  전환에는 zsh 또는 fish 로그인 셸 필요 — 다른 로그인 셸에서는 오류로 중단되고 아무것도 바뀌지 않음.
  자세한 내용은 [CLI](/docs/cli.md) 문서 참조 — `openusage` 명령줄 도구는 필요 없음.
  토글은 로컬에서 사용 가능한 로그인 정보가 필요하며 **Session Expired**나 **Sign-In Needed**이면 비활성.
  **Not Checked**, **Checking**, 일시적인 **Refresh Failed** 자체로는 전환을 막지 않음.
  등록 계정이 남아 있는 한, 나중에 재로그인이 필요해져도 계정 하나는 선택 상태 유지.
  상태가 바뀌어도 다른 계정을 자동 선택하지 않음.
  이미 실행 중인 세션은 절대 바뀌지 않음.
  선택된 Claude 계정으로 일반 터미널에서 `claude`의 `/login` 또는 `claude auth login`을 실행해 다시 로그인하면, OpenUsage가 공유 홈의 로그인을 검증하고 같은 계정명에 저장된 인증 정보와 프로바이더 신원을 자동 교체.
  이 경로는 **Sign In Again**이나 OpenUsage 재실행이 필요 없으며, UI가 아직 변경을 감지하지 못했을 때는 수동 새로 고침으로 충분.
  이전과 다른 Claude 신원으로 로그인해도 선택된 계정명과 선택 상태를 유지하며, 다른 계정명을 조용히 선택하지 않음.
- Customize에는 Claude 또는 Codex가 한 번만 나오고, 켜기/끄기는 해당 프로바이더 계열의 모든 계정 카드에 적용.
  **Single Card** 모드의 대시보드 계정 선택기는 여기 등록한 계정 중 표시 가능한 계정을 나열하고, 카드에 어느 계정의 사용량을 표시할지 선택 — 미등록 공유 홈 로그인은 추가 선택지에서 제외.
  Settings 또는 대시보드 우클릭 메뉴에서 전환을 확정하면 개별 카드 표시 중에도 저장된 대시보드 선택이 같은 계정으로 한 번 이동 — 메뉴 막대 별표는 프로바이더 설정이라 그대로 유지.
  이후 대시보드 선택기 변경은 보기 전용이며 터미널 전환을 다시 실행하지 않음.
  비활성 계정의 사용량은 Keychain 인증 스냅샷의 토큰으로 프로바이더 API에서 조회.
  스냅샷의 토큰이 만료되면 갱신된 토큰을 같은 스냅샷에 다시 저장.
  Codex 갱신 도중 그 계정을 선택하면, 공유 인증 원문이 요청 시작 시 스냅샷 또는 이전 동기화 실패로 남은 원문과 같을 때만 공유 홈에도 갱신본 반영.
  공유 홈 저장 실패 시 오류를 안내하고, 다음 전환에서도 갱신된 스냅샷을 이전 공유 토큰으로 덮어쓰지 않도록 보존.
  저장 실패 뒤 공유 파일 읽기까지 실패하면 가능한 이전 인증들을 함께 기억해 최신 토큰 보존.
- **Manage…**에서 계정 이름 변경, 세션이 만료된 계정의 공식 로그인 재실행, 계정 제거 처리.
  편집 가능한 필드는 계정명뿐.
  **Sign In Again**은 앱 안의 복구 경로로 계속 제공하지만, 선택된 Claude 계정을 일반 터미널에서 재인증한 경우에는 필수 아님.
  **Sign In Again**은 완전하고 검증 가능한 프로바이더 로그인이면 계정명에 저장된 인증 정보와 프로바이더 신원을 교체.
  Manage는 이 복구 동작과 함께 현재 실패의 상세 원인 표시.
  재로그인 완료 시 해당 계정의 이전 확인 결과를 해제하고, 프로바이더가 켜져 있으면 신원이 같아도 새 확인 요청.
  확인 성공 시 **Ready** 복구 — 로그인 변경 전에 시작된 요청의 결과는 폐기.
  프로바이더 신원이 바뀌거나 다른 계정명에도 같은 신원이 저장돼 있어도 계정명을 바꾸거나 다른 계정을 선택하지 않음.
  제거는 그 계정의 OpenUsage 로그인 작업 공간을 먼저, 다음으로 Keychain 스냅샷을 지우고, 마지막에 레코드 등록 해제.
  `~/.claude`와 `~/.codex` 데이터는 절대 건드리지 않음.
  둘 중 하나라도 삭제가 실패하면 다시 시도할 수 있도록 계정 등록 유지.
  작업 공간 삭제가 실패한 경우에는 스냅샷도 전환 가능한 상태로 남김.
  다른 계정이 있는 동안에는 선택된 계정 제거 불가 — 먼저 전환 필요.
- 계정 추가·이름 변경·재로그인·제거는 대시보드 계정 카드와 계정 선택기를 즉시 갱신.
  OpenUsage 재실행 불필요.
- 저장된 계정 레지스트리를 디코딩하거나 검증할 수 없으면 OpenUsage는 원본 데이터를 그대로 둠.
  레지스트리를 빈 목록으로 바꾸는 대신 Accounts에 오류를 표시하고 계정 변경 차단.

### Usage Cards

Accounts 맨 위의 **Usage Cards** 설정 하나로 계정 기능을 지원하는 모든 프로바이더에 같은 표시 모드 적용.
한 프로바이더에 등록 계정이 둘 이상일 때만 표시하며, Claude 1개와 Codex 1개는 이 조건에 해당하지 않음.
계정 수가 줄어 설정이 숨겨져도 저장된 선택 유지.

| 옵션 | 동작 |
| --- | --- |
| **Single Card** | 기본값.<br>선택한 계정을 프로바이더 이름 아래 표시하고 대시보드 계정 선택기 유지. |
| **Separate Cards** | 사용 가능한 계정 카드를 `Claude: Account 1`, `Codex: Account 2` 같은 고정 제목 `{Provider}: {name}`으로 각각 표시.<br>헤더 계정 선택기 없음. |

`{name}`은 계정의 기존 **Account Name** 사용.
제목 형식은 편집 불가이며, **Manage…**에서 계정명을 변경하면 카드 제목과 Share Screenshot 제목에 즉시 반영.
계정 표시와 공유 레이아웃 동작은 [대시보드](/docs/dashboard.md) 참조.

표시 모드는 즉시 적용되고 재실행 후에도 유지.
공통 선택을 저장하기 전에는 초기 개발 빌드의 프로바이더별 설정 중 **Separate Cards**가 하나라도 있으면 승계하며, 그렇지 않으면 **Single Card** 사용.
모드를 변경해도 대시보드 선택을 보존하며 터미널 계정 전환이나 사용량 새로 고침은 실행하지 않음.
**Single Card**로 돌아오면 이전 선택이 여전히 표시 가능한 경우 복원하고, 그렇지 않으면 사용 가능한 계정 선택.
한 프로바이더의 마지막 등록 계정을 제거하면 해당 프로바이더는 단일 카드로 돌아가지만, 이후 추가할 계정을 위해 저장된 설정 보존.
계정 레지스트리를 읽을 수 없는 경우에도 단일 카드를 사용하며 레지스트리가 복구될 때까지 설정 보존.

### 계정 순서

한 프로바이더에 등록 계정이 둘 이상이면 별도 핸들 없이 계정 행 블록을 드래그해 해당 프로바이더 목록 안에서 이동.
로그인·갱신 상태와 관계없이 행 이동 가능하며 Claude와 Codex 사이의 이동은 허용하지 않음.
**Manage…**와 전환 토글 클릭은 정렬을 시작하지 않고 기존 동작 유지.
드래그 중 목록 위·아래 가장자리에서 자동 스크롤.
VoiceOver는 계정 행에 **Move Up**과 **Move Down** 동작을 제공하고 계정 위치 안내.

계정 순서는 Settings, **Single Card** 계정 선택기, **Separate Cards**, **Options → Share Screenshot**에 해당 계정이 표시되는 곳마다 즉시 적용.
드래그로 바꾼 순서는 Settings 이탈·팝오버 닫기·앱 재실행 후에도 유지.

기본 순서는 계정 등록순이며 새 계정은 사용자 지정 순서의 마지막에 추가.
이름 변경, 재로그인, 활성 계정 전환, 표시 모드 변경과 재실행 후에도 순서 유지.
계정 제거 시 남은 계정의 상대 순서를 유지하며 같은 이름을 다시 등록하면 새 계정으로 마지막에 추가.
일시적으로 사용량 카드가 없는 계정도 Settings에서 위치를 유지하고, 카드가 다시 사용 가능해지면 해당 위치로 복귀.

Customize는 프로바이더 블록 전체, Settings는 블록 내부 계정 순서 관리.
어느 쪽을 이동해도 다른 쪽 순서는 유지하며, Customize 실행 취소나 **Reset All**은 계정 순서를 초기화하지 않음.
계정 정렬은 계정 선택, 인증 정보, 지표 레이아웃과 사용량 데이터를 변경하지 않음.
표시 모드와 계정 순서는 이 Mac에만 저장하며 iCloud 동기화에서 제외.

## iCloud 동기화

**Sync Across Macs**(Mac 간 동기화)는 기본값 꺼짐.
켜면 앱의 비공개 iCloud 컨테이너로 정규화된 OpenUsage 기록을 공유하고, 같은 iCloud 계정으로 로그인한 Mac들의 로컬 토큰과 지출을 합산.
사용량 기록은 일반 5분·Claude 15분 배치가 끝난 뒤 저장.
설정에는 Mac별 상대 **Updated** 시각이 표시되며, iCloud 사용 불가·불러오기·저장·잘못된 파일 형식 상태도 함께 표시.
무엇이 포함되고 어느 화면이 합산 값을 쓰는지는 [iCloud 동기화](/docs/icloud-sync.md) 참조.

## 사용량 표시

| 설정 | 옵션 | 동작 |
|---|---|---|
| Show Usage As(사용량 표시 방식) | Used / Left | 상한이 있는 지표를 "48% used"로 읽을지 "52% left"로 읽을지 — 기본값은 Used이며, 헤드라인 클릭과 같은 토글. |
| Reset Times(초기화 시각 표시) | Countdown / Exact time | "Resets in 3h 25m" 대 "Resets today at 6:38 PM" — 기본값은 Exact Time이며, 리셋 라벨 클릭과 같은 토글. |
| Always Show Pacing(사용 속도 항상 표시) | 끄기 / 켜기 | 켜기(기본값)는 사용량이 있고 초기화 기간이 있는 지표에 사용 속도 표시 — 정상 궤도인 행에는 예측치("~33% left at reset")와, 꾸준히 썼다면 지금 어디쯤일지 알려 주는 균등 속도 눈금 추가.<br>끄면 한도에 가깝거나 넘긴 지표로만 제한.<br>사용량이 0이거나 초기화 기간이 없는 지표에는 예측 문구·눈금 미표시. |

## Soft Limit

- **Enabled(활성화)**: 기본값 끄기, 활성화 전 확인 필요.
  지원 대상 진행 막대에 안내선 표시.
  클라이언트·계정 범위 검증 전 자동 취소 차단.
- **Window(기간)**: 5 Hours / Weekly 중 하나 선택, 기본값 Weekly.
  Soft Limit을 켠 동안에만 표시.
  일간·월간·잔액·상한 없는 지표 제외.
- **Threshold(임계값)**: 1%–100% 정수 직접 입력.
  안내선과 취소 엔진이 사용하는 사용률 임계값이며, 프로바이더가 강제하는 한도와 별개인 사용자 기준선.
  저장된 임계값이 없으면 기본값 90%.
  Soft Limit을 켠 동안에만 표시.

Soft Limit 설정은 이 Mac에 저장.
안내선은 선택 기간을 명시적으로 지원하는 프로바이더 진행 막대에 적용.
Enter를 누르거나 입력을 마치면 유효한 임계값 적용.
잘못된 입력은 이전 설정을 유지하고 안내 문구 표시.
Soft Limit을 껐다 켜도 저장된 임계값 유지.
Used와 Left를 전환하면 안내선 위치만 반전하며, 95% used와 5% left는 같은 임계값.

### 현재 지원 범위

**현재 앱에서는 자동 취소 사용 불가.**
로컬 Codex App Server의 취소 연결은 구현됐으나, 연결된 클라이언트와 사용량 계정이 일치하는지 검증하는 기능은 미완료.
따라서 **Enabled**를 켜도 자동 취소는 차단된 상태 유지.
독립 Codex CLI·앱·IDE 세션과 다른 프로바이더도 자동 취소 대상에 포함되지 않음.

**Connect Codex**는 사용자가 실행할 명령의 순서 안내.
먼저 `codex app-server daemon start`, 다음으로 `codex --remote unix://` 실행.
OpenUsage가 명령을 대신 실행하거나 기존 세션을 재시작하지 않음.
제어 소켓은 비어 있지 않은 `CODEX_HOME` 아래에서 탐색하며, 미지정·빈 문자열이면 `~/.codex` 사용.
직접 소켓과 심볼릭 링크를 모두 처리하며, 연결 전 실제 소켓의 소유자·접근 권한 확인.
로컬 연결 절차는 공식 [Codex App Server 문서](https://learn.chatgpt.com/docs/app-server) 참조.

### 취소 엔진의 적용 조건

아래 규칙은 클라이언트·계정 범위 검증이 완료된 연결을 전제로 구현된 내부 동작.
현재 앱에서는 앞의 검증 기능이 미완료여서 실제 자동 취소까지 진행되지 않음.

- 활성화·설정 변경 후에는 다음 한도 조회 성공까지 대기.
  설정 변경 전에 관측한 값은 요청이 나중에 끝나도 제외.
- 재로그인·API 키 변경·계정 동기화 오류 시 기존 판정 무효화.
  다음 한도 조회 성공까지 대기.
- 반올림 전 사용률이 임계값 이상이고 관측 시점부터 5분이 지나지 않은 경우에만 취소 허용.
  캐시·조회 실패·429 대기 결과로 관측 유효 기간을 연장하지 않음.
- 조건을 만족하면 새 작업을 포함해 연결된 작업을 2초마다 확인.
  클라이언트를 닫거나 대화를 삭제하지 않고 진행 중 응답(turn)만 중단.
  Codex가 대화 제목을 생성하는 임시 보조 작업은 제외.
  일반 임시 대화의 turn을 조회할 수 없으면 취소 조회 실패로 표시.
- 취소 실패 후에는 최소 10초 대기하며, 작업당 총 3회까지 시도.
  확인된 취소는 반복하지 않음.
- 취소 확인 중 검사가 중단되면 완료 대신 대기 상태로 표시.
  **Cancellation Status**에서 확인된 중단·미연결·미지원을 구분하고 실패도 표시.

한도 조회는 일반 5분·Claude 15분 주기이므로, 이 엔진만으로 추가 사용 방지를 보장할 수 없음.
이전에 안내선을 켠 설정만으로 자동 취소에 동의한 것으로 처리하지 않으며, 활성화 전 재확인 필요.

## 알림

사용량이 한도에 가까워지는 상태를 지켜보려고 팝오버를 계속 열어 둘 필요 없이, 지표 잔량이 부족해지거나 사용 속도가 나빠지면 OpenUsage가 macOS 알림으로 통지.
알림은 앱이 메뉴 막대에서 실행 중이면 동작하며, 팝오버가 닫혀 있어도 마찬가지.

| 설정 | 옵션 | 동작 |
|---|---|---|
| Almost Out(거의 소진) | 켜기 / 끄기 | 초기화 기간이 없는 잔액까지 포함해, 지표 잔량이 10% 아래로 내려가면 통지. |
| Cutting It Close(한도에 근접) | 켜기 / 끄기 | 이번 기간 종료 시 지표 잔량이 거의 남지 않아 한도에 가깝게 끝날 전망이면 통지. |
| Will Run Out(곧 소진) | 켜기 / 끄기 | 지표가 초기화 전에 소진될 전망이면 통지. |
| Codex Reset Watch | 켜기 / 끄기 | 공개 Reset Watch에서 새 유효 예측이나 리셋 예정 정보를 확인하면 통지. |

앞의 세 할당량 알림은 새로 임계선을 넘거나 속도가 나빠질 때 발생하고, 그 상태가 그대로인 동안에는 중복을 제거하므로 새로 고침마다 반복되지 않음.
OpenUsage를 실행한 시점에 이미 나쁜 상태인 할당량은 통지 없이 기준선으로만 기록.
카드의 계정 신원이 바뀌거나 제거되면 알림 기준선 초기화; 교체 계정의 첫 관측에서는 할당량 경고를 발생시키지 않음.
Claude 또는 Codex 카드의 계정을 식별할 수 없는 경우, 계정 목록 변경 시에도 해당 카드의 알림 기준선을 초기화하고 진행 중인 알림 중단.
계정 교체 시 이전 계정의 미제출 할당량 알림은 중단하고, 이미 제출 중인 요청은 완료 후 제거.
회복한 뒤 다시 나빠지면 알림 재활성화, 새 초기화 기간이 시작되면 초기화 기반 기록도 정리.
같은 초기화 기간의 사용량이 0으로 돌아온 것만으로는 사용 속도 회복을 추정하지 않으며, 속도 기반 알림의 중복 억제 기록 유지.
**Almost Out**은 남은 비중만 기준이라, 초기화 기간이 없는 상한 잔액에도 동작.
**Cutting It Close**와 **Will Run Out**은 초기화 기간의 사용 속도 정보 필요.
데이터를 읽을 수 없는 지표는 알림 제외.
세 할당량 알림을 모두 꺼도 **Codex Reset Watch** 알림은 별도 설정에 따라 동작.
여러 알림이 동시에 발생하면 하나의 그룹 배너로 묶임.

**Codex Reset Watch**는 Codex 프로바이더가 켜져 있으면 지표 표시·메뉴 막대 별표 없이 알림만 사용 가능.
처음 켠 뒤 조회에서 현재 유효한 이벤트를 확인한 경우도 통지 대상.
기록이 남아 있는 공개 이벤트는 이 Mac에서 한 번 통지하며, 계정 수와 관계없이 같은 알림은 하나만 발생.
같은 이벤트의 확률·투표율·예정 시각 수정으로 반복하지 않으며, 예측 이후 리셋 예정 정보를 확인하면 추가로 한 번 통지 가능.
중복 방지를 위해 최근 확인한 이벤트 식별자 128개를 저장하며, 이 기록은 앱 재시작 후에도 유지.
조회 실패·취소, 만료된 예측, 이미 지난 리셋 예정 시각, 식별할 수 없는 이벤트는 알림 제외.
공개 예측을 알리는 기능이며 개인 계정의 사용량 리셋 완료를 의미하지 않음.
자세한 조건은 [Reset Watch](/docs/providers/codex.md#reset-watch) 참조.

네 알림 모두 기본값 꺼짐.
처음 하나를 켤 때 OpenUsage가 알림 권한 요청 — 거절하거나 나중에 시스템 설정에서 OpenUsage 알림을 끄면 알림 섹션 헤더에 경고 표시가 붙고, 다시 켤 수 있도록 토글 아래에 "Open System Settings"(시스템 설정 열기) 버튼 등장.
알림 제목은 알림 이름이며 본문은 상태 설명.
할당량 알림의 부제목은 프로바이더와 지표, Reset Watch의 부제목은 예측·예정 구분.
알림을 누르면 대시보드 화면으로 팝오버 열기.

## 개인정보

| 설정 | 옵션 | 동작 |

## Tokscale CLI 동기화

Tokscale 섹션의 **Usage Sync**는 로컬 사용량을 공개 Tokscale 프로필에 게시하는 기능.
iCloud 동기화, Share Anonymous Usage, 프로바이더 활성화, 일반 새로 고침과 독립.
앱이나 Settings를 여는 것만으로는 Tokscale 명령을 실행하지 않음.
`openusage` 명령과 로컬 HTTP API 요청도 Tokscale 실행을 시작하지 않음.
공개 범위는 [개인정보 및 사용 데이터](/docs/privacy.md#tokscale-공개-공유), 외부 서비스 정책은 공식 [Tokscale Privacy Policy](https://tokscale.ai/privacy) 참조.

### 기기 이름

기기 이름 관리 버튼에서 **Tokscale Device Name** 창 열기.
이 창은 Tokscale에 전달할 이 Mac의 이름을 별도로 지정하는 기능이며, 기본값은 미지정.
이름은 앞뒤 공백을 제거한 뒤 비어 있지 않아야 하며, UTF-8 기준 최대 120바이트 허용.
제어 문자는 허용하지 않음.
저장한 이름은 이 Mac에만 보관하며, 이름 저장만으로 명령이나 네트워크 요청을 시작하지 않음.
창을 다시 열거나 앱을 재시작해도 저장한 이름 유지.
이후 제출 명령에 `TOKSCALE_DEVICE_NAME`으로 전달.
이 설정은 Tokscale의 기기 ID를 변경하지 않음.
전달한 이름의 공개 프로필 반영은 Tokscale CLI와 서버의 처리에 따름.

**Remove OpenUsage Override**는 OpenUsage에 저장한 이름만 제거.
Tokscale의 기존 공개 이름은 삭제하지 않음.
이후 제출에서는 OpenUsage가 이름을 덮어쓰지 않으며, 환경 변수와 저장된 기기 기록의 이름 처리는 Tokscale에서 결정.

### 사용량 제출

**Sync**를 선택하면 프로바이더·날짜·OpenUsage 데이터를 명령 인자로 넘기지 않고 다음 명령을 한 번 실행:

```sh
bunx tokscale@latest submit
```

선택적 GitHub 별표 요청을 거절하도록 `n`과 줄바꿈을 한 번 전달한 뒤 입력 종료.
포함할 소스와 필드는 Tokscale에서 결정.
검토한 CLI 버전은 사용량·클라이언트·모델·기기·발견된 MCP 서버 정보를 공개 프로필에 포함 가능.
해당 프로필은 검색 결과에 노출될 수 있으며, 검토 시점과 제출 항목은 [개인정보 문서](/docs/privacy.md#tokscale-공개-공유) 참조.
`@latest`는 OpenUsage 출시 이후 동작이 바뀐 패키지를 내려받아 실행할 수 있음.
패키지 선택은 사용자 Bun 설정을 따르며, 홈 디렉터리 아래의 일치 패키지를 우선할 수 있음.

**Sync** 선택 후 앱의 처리 순서:

1. 앱 환경 변수의 `PATH`, 로그인 셸의 `PATH`, Bun 설치 경로에서 `bun`과 `bunx` 탐색.
2. Bun이 없으면 공식 설치 프로그램 실행.
   설치 중에는 **Installing Bun…** 표시.
3. 새로 설치한 경우에는 설치 경로의 `bun`과 `bunx` 검증.
   설치·검증 실패 시 제출을 중단하고 수동 설치 안내 표시.
4. 사용할 Bun이 확인되면 앱 재시작 없이 제출 명령 실행.
5. 명령이 0이 아닌 종료 코드와 `Not logged in.` 문구를 반환하면 **Log In…** 표시.
   그 밖의 0이 아닌 종료 코드는 일반 실패로 표시.

명령에는 앱과 로그인 셸에서 명시적으로 허용한 언어·네트워크·패키지 저장소·Tokscale 인증·설정·소스 경로 변수만 전달.
`HOME`과 작업 디렉터리는 현재 macOS 사용자의 홈으로 고정하고, 무관한 비밀 값과 미등록 변수는 제외.
저장한 기기 이름은 `TOKSCALE_DEVICE_NAME` 값만 덮어씀.
지원 소스 탐색은 Tokscale에서 수행.
추가 경로의 환경 변수가 허용 목록에 없으면 `TOKSCALE_EXTRA_DIRS` 사용.

### 로그인 후 다시 제출

로그인 전 안내에는 GitHub 신원 정보 저장, 공개 프로필의 사용자명·아바타·표시 이름 노출 가능성 포함.
로그인 명령은 개인 토큰 이름으로 `CLI on <hostname>` 사용.

1. **Log In…**을 선택해 **Log In to Tokscale** 창 열기.
2. 창 안의 **Log In** 선택.
   앱은 표준 입력 없이 `bunx tokscale@latest login`을 한 번 실행.
3. 승인 대기 중 표시되는 브라우저 주소와 사용자 코드로 로그인 승인.
4. 로그인 창에 완료 상태가 표시되면 **Done**으로 창 닫기.
5. Settings 카드의 **Tokscale Login Finished. Sync Has Not Started.** 표시 확인.
6. 사용량을 제출하려면 카드의 **Sync**를 다시 선택.

로그인 완료만으로 사용량을 자동 제출하지 않음.
만료되거나 폐기된 저장 인증 정보는 OpenUsage의 로그인 안내로 복구되지 않을 수 있으므로 Tokscale 자체 CLI에서 복구.

### 결과와 재실행

동시에 Tokscale 명령 하나만 실행.
카드에서 Bun 설치 중·명령 실행 중·로그인 필요·완료·실패 상태 구분.
명령 출력은 ANSI·제어 시퀀스를 제거하고 크기를 제한해 표시.
완료·실패 후에도 Settings 카드의 **Done**으로 닫거나 다음 작업을 시작하거나 앱을 종료할 때까지 출력 유지.
로그인 창이 열려 있으면 같은 로그인 출력 표시.

Settings 카드의 **Done**은 결과·명령 출력·오류를 비우고 초기 카드로 복귀.
로그인 창의 **Done**은 창만 닫으며 카드의 결과와 출력은 유지.
기기 이름과 Tokscale 인증은 유지하며, 설치·명령 실행 중에는 Done 사용 불가.
제출 명령의 종료 코드가 0이면 결과를 닫기 전까지 **Sync** 비활성화.
**Done**으로 결과를 닫은 시점부터 최소 10분간 비활성화 유지.
**Sync Available at**은 다음 실행 가능 시각 표시.
해당 시각에는 버튼만 활성화하고 자동 제출하지 않음.
오류·미로그인 안내·로그인 결과를 닫으면 새 대기 시간 없이 사용자가 재시도 가능.
대기 상태는 Settings를 닫아도 유지하며 앱 재시작 시 초기화.
종료 코드 0은 제출할 사용량이 없는 경우에도 가능하므로 업로드 성공을 보장하지 않음.

### Bun 자동 설치 조건

Bun이 없을 때만 공식 [설치 프로그램](https://bun.com/docs/installation) 실행.
현재 사용자 홈 아래에서 앱의 경로 검증을 통과한 `BUN_INSTALL`, 또는 기본값 `~/.bun`에 설치.
설치 프로그램은 로그인 셸 설정 파일을 갱신할 수 있음.
조건에 맞지 않는 `BUN_INSTALL`은 수정하지 않고 실패와 수동 설치 안내 표시.
사용 가능한 기존 Bun은 교체하지 않음.
기존 설치 탐색은 심볼릭 링크나 사용자 홈 밖의 경로도 허용하며, 홈 경로 제한은 자동 설치에만 적용.
Bun은 있지만 사용 가능한 `bunx`가 없으면 재설치하지 않고 오류 표시.

## 고급

| 설정 | 옵션 | 동작 |
|---|---|---|
| Log Level(로그 레벨) | Error / Warning / Info / Debug | 앱이 로그 파일에 기록하는 상세 수준.<br>기본값은 Info이며 재실행 후에도 유지, 문제를 재현하는 동안에는 Debug로 올리기.<br>즉시 적용. |
| Copy Log Path(로그 경로 복사) | 버튼 | 로그 파일 경로(`~/Library/Logs/OpenUsage/OpenUsage.log`)를 클립보드에 복사. |
| Reveal in Finder(Finder에서 보기) | 버튼 | 로그 파일이 선택된 Finder 창 열기. |

서브시스템 태그, 파일 크기 상한, 민감 정보 마스킹의 범위와 한계는 [로깅](/docs/logging.md) 참조.

## 업데이트

업데이트 섹션은 서명된 업데이트 피드를 포함한 공식 패키지 빌드에만 등장.
로컬 개발 빌드에는 없음.

| 설정 | 옵션 | 동작 |
|---|---|---|
| Update Automatically(자동 업데이트) | 켜기 / 끄기 | Sparkle이 백그라운드에서 업데이트를 확인할지 여부.<br>꺼 두어도 수동 확인은 가능. |
| Beta Updates(베타 업데이트) | 켜기 / 끄기 | 받을 수 있는 업데이트에 프리릴리스 빌드 추가.<br>안정 릴리스는 어느 쪽이든 계속 제공. |
| Check for Updates…(업데이트 확인…) | 버튼 | 수동 업데이트 확인을 시작하고 Sparkle 업데이트 창 열기. |

대시보드 배너, 채널, 서명 검증은 [업데이트](/docs/updates.md) 참조.

## 버전

앱 버전은 팝오버 푸터에 표시.

설정은 업데이트 후에도 그대로 유지 — 레이아웃, 별표, 환경 설정, 메뉴 막대 단축키 모두 보존.
업데이트로 설정 저장 방식이 바뀌면 실행 시 기존 설정을 제자리에서 업그레이드하고, 중간 버전을 몇 개 건너뛰었다면 해당 단계도 순서대로 적용.
초기화되는 것은 없음.
(초기 베타는 업데이트마다 모든 설정을 지웠지만, 이제는 그렇지 않음.)

켜 둔 프로바이더도 업데이트 후에 그대로 유지 — 사용자 선택을 덮어쓰지 않음.
완전히 새로 설치한 경우에는 Mac의 로컬 인증 정보나 사용 흔적으로 처음 켤 프로바이더 결정([대시보드 § 첫 실행](/docs/dashboard.md#첫-실행) 참조).
업데이트로 새 프로바이더가 추가되면 해당 프로바이더만 같은 기준으로 한 번 확인.
로컬 감지 조건을 만족하면 자동으로 켜고, 기존 프로바이더의 선택은 유지.
[활성화되는 프로바이더](/docs/provider-enablement.md) 참조.
